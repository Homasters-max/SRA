## Context

Аудит Graft после [ADR-0028](WARRANT-ADR-0028-graft-adoption.md) — отчёт
[docs/process/graft-audit.md](../process/graft-audit.md). Четыре направления, каждое сверено с эталоном:

- **Содержимое графа** против компилятора TypeScript (207 файлов). Рёбра вызовов точны (99,4 %), но неполны:
  **вызовы через порты** (`ctx.git.head()`, `ctx.checks.run()`) — **0 из 284**; вызов из другого файла имени,
  определённого в нескольких файлах, — 4 из 141; строка под вызывающим в выводе `callers` — не место вызова в 31 %.
  `cs callers CheckRunner.run` отвечает «no indexed callers» без предупреждения при реальном вызове `check.ts:225`.
  Правило 3 навыка (перед сменой сигнатуры — `callers`, каждое место учесть) опиралось на ответ, систематически
  пустой для архитектуры портов [ADR-0025](WARRANT-ADR-0025-test-levels.md). Бенчмарк этого не видел: 8 вопросов
  оказались по силам и графу, и grep.
- **Поле** (`test-levels`, группы `[A]`): тихих промахов в коммитах нет; `cs grep` = `git grep` 27 из 27. Но 55 из 119
  чтений кода — целые файлы через `offset=1, limit=N` (навык сам допускал «диапазон `1..N`»), детектор их не считал;
  шаблон `a\|b` в `cs grep` молча ничего не находит.
- **Обёртка `cs.js`:** проверялась версия одного пакета, а запускался первый `graft` на PATH; запрет `--dir`
  обходился позиционным каталогом; `GRAFT_*` из окружения проходили в graft; вывод `callers` не ограничен (правило 5
  неверно); тестов нет. Детектор отступлений пропускал `rg`, `git grep`, Grep без пути и ложно срабатывал на
  `git commit -m "…graft ask…"`. Телеметрия установки ушла до `DO_NOT_TRACK` (порядок graft.md §2).
- **Хуки Claude Code** (документация + зонд `claude -p` с субагентом, Claude Code 2.1.263): `PreToolUse` /
  `PostToolUse` из проектного `.claude/settings.json` срабатывают в субагентах, вход несёт `agent_id` / `agent_type`,
  `additionalContext` доходит до модели, сделавшей вызов; **`SessionStart` до субагентов не доходит**, `SubagentStart`
  добавляет контекст только субагенту; хуки слоёв настроек сливаются; файл только с `hooks` права не трогает.
- **Архитектурный аудит** той же даты (отдельная сессия, навык `architecture-audit`): рёбер импорта в выводе `cs` нет
  (у каждого файла «0 in-edges»), граф модулей и циклы пришлось восстанавливать своим парсером текста `cs grep`
  (~25 с; `grep` режет выдачу на 300 совпадениях; первая версия парсера молча приписала совпадения не тем файлам);
  `--json` обёртка не пропускала; `ask` — лексический. При этом в индексе 715 рёбер `imports` файл → файл (точность
  100 %, полнота 99,6 %) — их просто не показывала ни одна подкоманда.

Вопрос владельца файла. [ADR-0014](WARRANT-ADR-0014-claude-code-enforcement.md) п. 4 отдаёт `.claude/settings.json`
генерации `warrant sync` (адаптер `claude`, later — [ADR-0018](WARRANT-ADR-0018-frontend-adapters.md),
[ADR-0023](WARRANT-ADR-0023-warrant-dev-frontend.md) п. 4); SEF сверяет конфиги движка с эталоном пакета байт в байт
(§7.3 черновика SEF, `ENGINE_CONFIG_MISMATCH`). `graft init` пишет `settings.json` сам — второй владелец; поэтому
ADR-0026 п. 2 хуки запретил.

## Decision

1. **`cs impact <символ>` — ответ на «что обновить при изменении символа».** Обёртка сводит `callers -d 1` графа и
   `grep` вызовов по имени (`\bname(`, `.name(`) в один список: место, объемлющий символ по графу, метка
   `[graph+grep]` / `[grep]` / `[graph]` (только граф — кандидат в ложное ребро), строка — из grep. Правило 3 навыка:
   перед изменением сигнатуры, переименованием, удалением, сменой поведения экспорта — `cs impact`; `callers` —
   нижняя граница (цепочки, «что сломается дальше»), не список правок.
2. **Зависимости и дубли — из индекса, а не из текста.** `cs deps <файл>` — импорты и кто импортирует (с пометкой
   `type-only`); `cs deps <каталог> --level N` — граф модулей (рёбра, Ca, Ce, нестабильность); `cs deps --cycles`
   (`--runtime` — без `import type`) — циклы; `cs dups` — имена, определённые в нескольких файлах (там граф теряет
   вызовы). `--json` — у всех команд; разбор вывода `cs` программой — только через `--json`.
3. **Обёртка** (ADR-0026 п. 2 — «только CLI через обёртку» — остаётся): graft запускается `node <пакет>/<bin>` из
   того пакета, чья версия проверена (`cross-spawn` не нужен — свежему worktree `npm ci` для `cs` не требуется);
   флаги и число позиционных аргументов — белым списком на подкоманду (иначе код 2); `GRAFT_*` из окружения
   удаляются; сборка индекса под замком; вывод `callers` ограничен; шаблон `a\|b` — код 2; таймаут. Логика —
   `scripts/dev/cs-lib.js` с unit-тестами.
4. **Регрессия графа.** `scripts/dev/graph-audit.js` сравнивает граф с эталоном компилятора TypeScript и с базой
   `scripts/dev/bench/graph-baseline.json`. **Уточняет ADR-0028 п. 4:** новая версия Graft принимается, только если
   (а) бенчмарк `[A]` — `accept` и (б) `graph-audit --baseline` не хуже базы. Бенчмарк дополнен различающими
   вопросами (вызовы через порты, одноимённые символы, ложное ребро `forward`, `runCli`) — снимает п. 6 ADR-0028
   («усиление — later»).
5. **Правило 2 навыка:** диапазон, покрывающий весь файл кода, — чтение целиком; файлы до 40 строк — исключение.
   Детектор отступлений считает и это.
6. **Хуки разработки WARRANT — `.claude/settings.json`, только ключ `hooks`**, команды — только
   `node "${CLAUDE_PROJECT_DIR}/scripts/dev/cs-hook.js" <event>`:
   - `SubagentStart` — указатель на навык `code-search`, `cs impact` и `cs map` (≈ 2 КБ) каждому субагенту; заменяет
     строку-прозу в промпте координатора (механизм вместо текста);
   - `PostToolUse` на `Read|Grep|Glob|Bash|PowerShell` — только у субагентов (`agent_id`): тот же детектор
     `deviationsOf`, что у `graft-metrics`, в режиме **предупреждения** (`additionalContext`). Один код и меряет, и
     подсказывает. Переход на запрет (`PreToolUse deny`) — отдельным решением после 2–3 групп без ложных срабатываний.
     **Уточнено ADR-0031:** запрет введён — `PreToolUse` на `Read|Grep|Bash|PowerShell` у субагентов, `permissionDecision:
     "deny"`; предупреждение `PostToolUse` — только для видимого по выводу.
   - **Не ставятся:** `PostToolUse` «callers после правки» (ответ неполон там, где важнее всего; сигнатуры ловит
     `typecheck`; часть правок идёт через Bash / PowerShell; уверенный неполный ответ хука опаснее его отсутствия) —
     пересмотр поверх `cs impact` с замером; `SessionStart` (не доходит до субагентов), `UserPromptSubmit` (токены на
     каждом ходе), `Stop` (индекс и так обновляется на запросе). Хуки самого graft (`graft init`) — по-прежнему нет.
   Форму файла держит мета-тест `npm test` (только `$schema` и `hooks`, только эти события и команды), а не
   `warrant validate`: продуктовый CLI о dev-инструментах не знает. ADR-0023 не меняется: это не `warrant guard` и не
   permissions.
7. **Владелец `settings.json` — один.** Сейчас — рукописный файл репозитория WARRANT (генератора нет). С появлением
   адаптера `claude` эти хуки становятся данными local-слоя проекта, `warrant sync` генерирует файл целиком, а эталон
   SEF для `.claude/**` — вывод `warrant sync` при том же `pack_hash` (правило W-11 распространяется на
   `.claude/settings.json`; приложение F черновика SEF, строка W-28). Глобальный `~/.claude` не трогаем.
8. **Наблюдение (ADR-0028 п. 5)** дополняется: следующие 2–3 группы сравниваются с базой `test-levels` `[A]` после
   пересчёта детектором п. 5 — отступления, байты чтений целиком, `explore_bytes`. Отчёт субагента получает раздел
   «пустые или неполные ответы `cs`».

## Consequences

- Навык `code-search`: правила 2–6 и таблица команд переписаны (`impact`, `deps`, `dups`, `--json`); помощник
  навыка `architecture-audit` переходит на `cs deps --json` / `cs dups --json` вместо разбора текста `cs grep`; [coordinator.md](../process/coordinator.md) —
  без строки про навык в промпте (её несёт `SubagentStart`), с новым разделом отчёта и сводкой для следующей части
  группы; [graft.md](../process/graft.md) — установка (`DO_NOT_TRACK` до `npm i -g`, `graft telemetry disable`),
  регрессия п. 4, хуки п. 6.
- Хуки срабатывают в каждом worktree репозитория сами (файл закоммичен) и не видны другим проектам. Отключить
  локально — `disableAllHooks` в `.claude/settings.local.json` (выключает и пользовательские хуки).
- Каждый вызов хука — запуск node (~150–200 мс); `PostToolUse` основной сессии выходит сразу.
- Одноимённые экспорты (`readRecords`, `classify`, `resolve`, `runCli`) не переименовываются под инструмент:
  `cs impact` показывает все определения и места.

## Alternatives

- **Сразу `warrant sync` генерирует `settings.json`** — отвергнуто сейчас: адаптера `claude` нет, dev-хуки
  появились бы в продуктовом CLI раньше продуктовых.
- **Проверка файла в `warrant validate`** — отвергнуто: продуктовый CLI не знает dev-инструментов; хватает мета-теста.
- **Хуки в frontmatter навыка или `.claude/agents/*.md`** — отвергнуто: навык регистрирует хуки только после вызова,
  агент — только для своего типа (Explore и `general-purpose` без них), frontmatter агента требует доверия workspace
  и под `-p`.
- **Глобальные хуки `~/.claude/settings.json`** — отвергнуто: сработали бы во всех проектах maintainer'а.
- **Мета-тест на одноимённые экспорты** — отвергнуто: подгонка имён кода под инструмент 0.x.
- **Только текстом в навыке («сверяй callers с grep»)** — отвергнуто: правило о форме без механизма (INV-04).
