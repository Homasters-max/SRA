## Context

Документы WARRANT были перенесены по ширине ~120 знаков посреди фраз. В Markdown такой перевод строки отображается пробелом — читателю он не нужен, а в исходнике рвёт фразы, портит diff и поиск.

- **Агент копирует форму из контекста.** Опыт 2026-09-28 в LATTICE: свежий Sonnet без контекста — 0 переносов, после чтения одного перенесённого документа — 12, с перенесённым промптом — 27. В SRA то же: субагент, чей `CLAUDE.md` ещё был с переносами, написал документ с 22 и 42 переносами, свежий `claude -p` из вычищенного checkout — 0. Перенесённые навыки, шаблоны промптов и документы заражают всё, что агенты пишут дальше.
- **Чистка:** PR #83 (2612 переносов в 121 файле, шаблоны промптов навыков и файлов передачи) и PR #84 (`docs/integrations/`, `lattice/`, 432) — инструментом `md-wrap` (парсер Prettier), файл пишется, только если разбор до и после эквивалентен. Склейка показала ещё одну ловушку: нумерованный список не с 1 сразу после абзаца по CommonMark — текст абзаца; эквивалентная склейка стёрла задуманный список (README черновика kb-domains, исправлено в PR #84).
- **Адрес по номеру строки хрупок.** Домены kb-search хранили ~1 800 адресов `файл.md:N`: к 2026-09-28 из 489 адресов с меткой («п. 3», «Consequences») 174 указывали не туда — документы правились после построения индекса, два ADR прочитаны со сдвигом, Change phase-4c уехал в архив; склейка сдвинула бы остальные. Метка при адресе всё это время находила место верно. kb-search заморожен решением maintainer'а (`docs/handoff/kb-domains.md`).
- Правило о форме принимается только с проверкой ([ADR-0032](WARRANT-ADR-0032-dev-context.md), INV-04). Парсера Markdown в зависимостях репозитория нет; детектор без парсера сверен с `md-wrap` на всём репозитории до и после чистки: 3 757 и 705 находок совпали, пропусков и ложных срабатываний — 0.

## Decision

1. **Абзац и пункт списка — одна строка любой длины.** Текст по ширине не переносится. Новая строка — только новый абзац, пункт списка, заголовок, строка таблицы, код. Строка, которая должна быть видна отдельно, — отдельный абзац или пункт; жёсткий разрыв (два пробела, `\`) не используется; нумерованный список, начатый не с 1, отделяется от абзаца пустой строкой. Правило действует для всех `.md` репозитория и для шаблонов промптов в навыках и файлах передачи (блоки `text`): строка промпта — один логический раздел. Длинный абзац труден для чтения — делить по смыслу на абзацы или список, не по ширине.
2. **Адрес места — самая точная из существующих форм: id элемента → раздел → файл.** Номер строки (`файл.md:42`) и отпечаток не пишутся: позиция сдвигается при любой правке, а id и заголовок агент находит одним поиском. Id объявляется в начале элемента, который он называет (заголовок, пункт, строка таблицы): `REQ-…`, `SCN-…`, `I-N`, `BL-N`, `п. N` ADR, `§N` документа. Отчёт о diff (находки ревью в теле PR) указывает строку diff — это не адрес в документе.
3. **Проверка — `packages/cli/test/unit/meta/md-form.test.ts`** (уровень `unit`, без процессов) с детектором `scripts/dev/md-form-lib.js`: переносы внутри абзаца и пункта, жёсткие разрывы, список, приклеенный к абзацу, адреса `путь.md:N` во всех `.md` репозитория. Вне правила, с причиной в тесте: архив Change (ADR-0021), `docs/archive/`, навыки OpenSpec (генерирует OpenSpec, ADR-0015 п. 6), фикстуры тестов. Исправлять — инструментом `md-wrap` (`~/.claude/tools/md-wrap`, вне репозитория) или руками.
4. **Храповик `PENDING`.** `openspec/specs/**`, `sra/skills/**`, `.claude/agents/warrant-reviewer.md` (генерирует `warrant sync` из шаблона в `packages/cli/src`) и `packs/core-sdd/golden/**` — policy-пути профиля `factory-change`: их чистит Change `md-format` (main specs — delta `MODIFIED` через archive-PR, навык — с поднятием версии, lock и golden). Change убирает строку из `PENDING`; чистый путь, оставленный в списке, роняет тест. Раздел `## Purpose` существующей main spec delta не меняет — `openspec archive` переносит его как есть (OpenSpec 1.13.1, `specs-apply`), а main specs меняются только archive-PR (ADR-0011): переносы Purpose — вне правила, тест их пропускает.

## Consequences

- `CLAUDE.md` — жёсткое правило; `docs/process/rules.md` — строка правила.
- Агенты больше не получают перенесённый текст из документов и навыков репозитория; хук на запись `.md` не нужен — после чистки агенты не переносят, а случайный перенос ловит тест.
- Индекс по номерам строк (kb-search) в репозитории невозможен: новый поиск по документации адресует по id и разделам.
- Навыки OpenSpec остаются с переносами (не наш текст; `openspec update` их перезапишет).

## Alternatives

- **Хук `PostToolUse` на запись `.md` (`md-wrap --hook`)** — отвергнуто: инструмент вне репозитория, CI его не видит; тест держит то же для всех.
- **Prettier в зависимостях и его парсер в тесте** — отвергнуто: новая зависимость ради одной проверки; детектор без парсера совпал с ним на всём репозитории.
- **Адреса строк с картой переписывания после каждой правки** — отвергнуто: опыт kb-search — треть адресов устарела за два дня, карта нужна на каждую правку любого документа.
- **Перенос по ширине, но везде одинаковый** — отвергнуто: форму копируют агенты, а перевод строки внутри фразы ломает поиск и diff.
