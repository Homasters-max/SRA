# Модель поиска: вопрос → группа-ответ, выбор LLM, вердикт, калибровка

## Проблема

- Поиск по домену выдаёт кандидатов с баллами Jev; какой ответ агент в итоге взял и пригодился ли он — не сохраняется, повтор вопроса снова стоит вызова Jev, ошибки выбора не видны (черновик 09, данные 2026-09-26: 16 живых вызовов, 19 % повторов).
- Maintainer (Q29, раунды 4–8): ответ — группа частей документов, её состав выбирает LLM из кандидатов Jev; найденная группа связывается с вопросом; неполную, избыточную или ошибочную группу нужно пересматривать системно; группа — минимальна, чтобы определять вопрос; работа — по доменам.
- Модель поиска стоит на ядре ([02-core-model](../2026-09-26-lattice-first/02-core-model.md)); термины — [04-terms](../2026-09-26-lattice-first/04-terms.md) (T-номера ниже), ID — [03-classification-ids](../2026-09-26-lattice-first/03-classification-ids.md).

## Идея

### 1. Объекты поиска

| Объект | Тип (реестр kb-search) | Пример ID | Что хранит |
|---|---|---|---|
| вопрос (T29) | `question` | `lexicon/QST-LCY-01J8…` | текст, домен, TERM-id ключа; алиас группы |
| группа-ответ (T21, T33) | `answer` | `lexicon/ANS-LCY-01J8…` | члены — нормы (≤ 7), метка, доверие |
| набор ответов (T34) | `answer-set` | `lexicon/ASET-01J8…` | члены — группы `answer` разных доменов |
| пул (T35) | snapshot `pool` | `SN-…` | кандидаты, поданные Jev (≤ 50) |
| оценка (T38) | `measurement` | `evidence/MEA-LCY-01J8…` | вопрос, пул, оценщик (`model`, `prompt_hash`, `state_hash`), баллы-меры, стоимость |
| вердикт (T39) | `observation` | `evidence/OBS-LCY-01J8…` | группа, snapshot выдачи, диагноз (п. 4) |
| вызов (T40) | `execution` | `runtime/EXE-01J8…` | вопрос, путь (кэш / mapping / Jev / сам), время |

Связи: вопрос `denotes` группу (mapping, T36); группа `denotes` нормы (членство); группа `cites` вердикты; вызов `causes` оценку (03-classification-ids п. 4).

### 2. Путь запроса

```
0. домен ← вызывающий (Change, группа задач, diff) │ нет → по терминам глоссария │ 2 домена → составной (п. 6)
1. LLM выделяет термины → TERM-id по глоссарию (Q35) → ключ = hash(домен + отсортированные TERM-id)
   термин вне глоссария → кандидат в алиасы (п. 5, путь B)
2. ключ → вопросы с mapping'ами (и негативные пары)
3. LLM сверяет: «мой вопрос — тот же, что сохранённый?» (текст к тексту; негативные пары — «не тот»)
   ├─ да → группа → snapshot → status:
   │        fresh → выдача без Jev
   │        stale → LLM перечитывает только изменённые члены (п. 7)
   │        broken → поиск пропавшей части по сохранённому вопросу
   └─ нет / ключа нет → 4
4. Jev по пулу домена → оценка (MEA) с баллами
5. LLM читает кандидатов, выбирает 1..7 норм, у каждой — причина (цитата) → новая группа (inferred) + mapping
   правильного нет среди кандидатов → 6
6. LLM ищет сама (cs, grep, чтение) → найденное = группа (via: self-search) + сигнал «Jev промахнулся» (п. 5)
```

Точный повтор текста — частный случай шагов 2–3: ключ совпал, сверка тривиальна. Вопрос с ID нормы (`REQ-…`, `ADR-…`) — прямой поиск по якорям до шага 1 (решено до grilling).

LLM шагов 1, 3, 5, 6 — вызывающий агент (Q32): `kb-search` возвращает кандидатов и сохранённые пары, агент отвечает командой выбора; отдельного вызова модели в навыке нет.

### 3. Гранулярность (Q36, Q54)

| Уровень | Правило |
|---|---|
| член | наименьший объект с одной нормой: unit / REQ / SCN / пункт ADR / TERM; не документ и не раздел |
| вопрос | атомарный — одна потребность в одном домене; составной разбивается на шаге 1 |
| группа `answer` | 1–7 членов; > 7 — сигнал разбить вопрос, не добавлять |
| зерно группы | (type, domain, потребность); зерно snapshot'а — (type, domain, [член@версия]) |

Группа **определяет вопрос**: вопросы с одной группой — перефразировки (алиасы группы, Q40′); их термины пополняют индекс ключей. Одна норма, записанная в двух местах, — дубль: сводится alias'ом объекта, а не второй группой.

Группа отвечает на **сохранённый вопрос, а не на задачу агента**: иначе она разрастается до «всего, что понадобилось». Правильная группа — **достаточна** (по ней можно ответить) и **минимальна** (у каждого члена своя причина, которую не покрывают остальные).

### 4. Вердикт (Q37, Q39)

Одна команда на каждую выданную группу, в конце использования (в отчётах субагентов — раздел «Нормы»):

```json
{ "group": "lexicon/ANS-LCY-01J8…", "snapshot": "SN-3fa29c0d71be44a2",
  "same_question": true,
  "answers_stored": "complete",
  "used": ["unit:lifecycle.cycle"], "unused": ["unit:lifecycle.gates"],
  "add": [{ "id": "spec/REQ-VER-007", "reason": "<цитата: чем отвечает на сохранённый вопрос>" }],
  "task_only": ["spec/ADR-0036"] }
```

| Вердикт | Диагноз | Действие |
|---|---|---|
| `same_question: false` | ошибка сопоставления (шаг 3), группа ни при чём | группу не трогать; негативная пара под ключом; новый вопрос — через Jev |
| `complete`, всё `used` | подтверждение | assertion «+» за каждое членство |
| `complete`, есть `unused` | возможно избыточна | слабое «−» членству `unused` |
| `incomplete` + `add` | неполна | posit'ы членства `add` с причиной |
| `wrong` | ошибочна | assertion «−» за mapping → `contested`; следующий запрос — через Jev |
| `task_only` | нужно задаче, не вопросу | в группу не входит; кандидат в отдельный вопрос |

### 5. Три способа ошибиться

| Ошибка | Обнаружение | Последствие |
|---|---|---|
| **A.** Jev вернул правильное, LLM выбрала не то | `wrong` / `incomplete` в вердиктах; другой выбор на тот же ключ; стенд | калибровка (п. 7) или `contested` |
| **B.** Jev не вернул правильного | шаг 6 | группа из найденного; вопрос + ожидаемые нормы → ловушка стенда; термины вопроса → кандидаты в `aliases` этих units; нормы нет ни в одном unit → дыра нарезки домена |
| **C.** Ответа нет | LLM: «нормы нет» | пустая группа допустима; устаревает с любой правкой домена (членов нет — привязка к версии домена) |
| коллизия ключа | «как работает archive» и «кто вправе запускать archive» → {archive} | шаг 3 сверяет тексты вопросов, не термины |

### 6. Домены (Q41′, Q46)

- Атомарный вопрос и группа `answer` — в одном домене: меньше пул Jev и контекст LLM, домены изолированы.
- Вопрос через домены — `answer-set` из групп по доменам, шаг на домен; разные задачи — разные задачи.
- Норма может входить в несколько доменов (домен — projection, Q7); группы при этом разные.

### 7. Калибровка (Q38, Q49)

- **Асимметрия:** добавить — по одному вердикту с причиной (нехватка стоит нового поиска); удалить — член `unused` в 3 разных сессиях и ни разу не `used` (лишний член стоит сотни токенов).
- **Каждое изменение** — posit членства + assertion сессии; группа та же, её snapshot — новый; mapping не меняется (Q47).
- **Раскачка:** один член добавлен и удалён дважды → `contested` → вопрос maintainer'у.
- **Граница размера:** если после добавления > 7 членов — не добавлять, разбить вопрос.
- **Устаревание — не калибровка:** изменилась версия члена → LLM перечитывает только его: отвечает → новый snapshot, доверие не меняется; не отвечает → вердикт `incomplete` / удаление по обычным правилам.
- **Доверие** — две оси LATTICE (02-core-model п. 4): `grounding` (`inferred` → `observed` → `declared`) и `epistemic_state` (`settled` / `contested` / `unresolved`). Выдача: `inferred` — с пометкой «не подтверждена», агент может отвергнуть; `contested` — всегда через Jev и выбор LLM.

### 8. Замкнутый цикл со стендом

Группы `observed` и `declared` — эталоны стенда (вопрос → ожидаемые нормы); стенд меряет по ним Jev; промахи Jev (путь B) дают ловушки и алиасы units. Поиск дообучается на работе агентов без отдельной разметки.

### 9. Что где реализуется

| Часть | Где | Когда |
|---|---|---|
| конвейер стадий, порты, стенд | навык `kb-search` (Q1) | рефакторинг после 09 и 01 (Q8) |
| ядро: ledger, группа, snapshot, доверие | LATTICE (02-core-model вопрос 1) | после slice LATTICE (Q10, Q12) |

| домены (units) | репозиторий (Q26) | каталог — 01 п. 2 |

## Вопросы для grilling

1. **Команда выбора и вердикта.** Одна команда `kb-search --verdict <файл|JSON>` для шага 5 (выбор = вердикт с `add`) и конца использования, или две (`--select`, `--verdict`)? Рекомендация: одна — выбор при создании — это вердикт `incomplete` пустой группы с `add`; меньше путей.
2. **Пустая группа (C)** — привязка к версии домена: версия домена = hash snapshot'а всех его units? Рекомендация: да — тот же механизм `status`, без особого случая.
3. **Шаг 0 по терминам**: если термины ведут в домен, которого нет (не нарезан), — поиск по документам целиком (как до доменов) с пометкой? Рекомендация: да; вопрос → сигнал «домен нужен» (Q27, по потребности).
4. **Верхняя граница пула** 50 (Q45) — из данных стенда (сейчас пул = весь домен: 164–206 units)? Рекомендация: пул = весь домен до 200 units; граница 50 — только когда домен больше, по top-N BM25 (замер цены — стенд).
