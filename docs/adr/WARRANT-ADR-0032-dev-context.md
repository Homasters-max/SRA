## Context

Сессии Claude Code, которые разрабатывают WARRANT ([ADR-0023](WARRANT-ADR-0023-warrant-dev-frontend.md)), передают друг другу контекст через `docs/NEXT-SESSION.md`. К 2026-09-24 файл вырос до 646 строк, и передача в нём — около 6 %:

| Содержимое | Строк | Где ему место |
|---|---|---|
| История: что закрыто, PR, SHA, версии | ~125 | вычисляется: `git log`, теги, `warrant status`, архив Changes |
| Решения grilling (P-, V-, G-, Q-, H-, D-) | ~160 | ADR или design.md Change |
| Долг (I-, A-, R-, «долг схем», backlog) | ~150 | реестр |
| Правила, конвенции кода, «чего не делать» | ~95 | постоянная инструкция |
| Список worktree | ~11 | вычисляется: `git worktree list` |
| Готовый запрос следующей сессии | ~37 | передача |

Следствия: каждая сессия и каждый субагент, которому координатор велит прочитать файл, получают сотни строк шума; параллельные сессии конфликтуют на одном файле; долг A-N читает оттуда `architecture.test.ts` — норма теста живёт в файле передачи. Смежные проблемы:

- **`CLAUDE.md`** — указатель в 9 строк на NEXT-SESSION. Change `agent-session-guide` (`CLAUDE.md`, `settings.json`) пропущен решением P-1 (grilling 2026-09-22) до фазы 4; P-1 же задал критерий: файл в `.claude/` автоматизирует процедуру, правило туда не пишется (каналы правил — [ADR-0022](WARRANT-ADR-0022-path-rules.md)).
- **auto-memory Claude Code** (`~/.claude/projects/D--project-SRA/memory/`) одна на все worktree репозитория и загружается в каждого субагента ([ADR-0027](WARRANT-ADR-0027-graft-tuning.md): индекс нарушил слепоту эксперимента). В ней лежит проектная история (хронология фаз, состояние Graft) — второй канал того же шума, вне репозитория.
- **Навыки разнородны**: процедуры — в `.claude/commands/` (`decision`, `group-done`, `group-stats`, `next-session`), справочники — в `.claude/skills/` (`code-search` 88 строк, `architecture-audit` 182), линзы `software-architect` и `grilling` — в глобальном `~/.claude/skills/` вне репозитория; общего шаблона, размера и проверки формы нет.
- **Навыки OpenSpec** ([ADR-0015](WARRANT-ADR-0015-openspec-sync-contract.md) п. 6) разложены дважды (`delivery: both` — `.claude/skills/openspec-*` и `.claude/commands/opsx/*`), и два из них опасны: `openspec-archive-change` сам сливает specs и переносит Change командой `mv` мимо `warrant archive` и gates `MERGED → ARCHIVED` ([ADR-0011](WARRANT-ADR-0011-pr-topology.md) п. 4), `openspec-sync-specs` пишет main specs вне archive-PR (ловит только CI, R-16). OpenSpec 1.13.1 выбирает состав профилем (`openspec config profile`, сейчас `core` — все шесть).
- **Хук `SessionStart`** [ADR-0029](WARRANT-ADR-0029-graft-audit-dev-hooks.md) п. 6 не ставил: до субагентов он не доходит. Для состояния сессии нужен именно он — состояние нужно основной сессии, не субагенту.

Решения приняты grilling'ом 2026-09-24 (Q1–Q15, maintainer принял все рекомендации).

## Decision

1. **У каждого вида знания одно место (Q1).**

   | Вид | Место | Кто пишет |
   |---|---|---|
   | Как работать: карта, навыки, жёсткие правила | `AGENTS.md` (п. 7) | человек, по ADR |
   | Решения | ADR (норма) или design.md Change (I-N, решения grilling по Change) | `/decision`, процедура ADR |
   | Состояние: ветки, worktree, теги, версии, открытые задачи | **не пишется** — вычисляется (п. 4) | `scripts/dev/brief.js` |
   | Долг | `docs/backlog.md` (п. 5) | сессия, закрывшая или нашедшая пункт |
   | Передача | `docs/handoff/<поток>.md` (п. 3), перезаписывается целиком | навык `handoff` |
   | Личное: кто пользователь, как с ним работать | auto-memory (п. 9) | модель |

   Факт, который можно вычислить из репозитория, прозой не записывается. Решения grilling по Change — в design.md этого Change; по процессу или норме — в ADR; в файл передачи — только ссылка.

2. **`docs/NEXT-SESSION.md` упраздняется (Q7, Q11).** Файл замораживается целиком как `docs/archive/2026-09-24-next-session.md`; ссылки из документов (P-1, V-9, H-1 и т. п.) переводятся на него, чтобы прежние решения оставались адресуемыми. Архив Changes неизменяем ([ADR-0021](WARRANT-ADR-0021-archive-immutability.md)), поэтому старые таблицы решений туда не дописываются. Живое извлекается: долг — в `backlog.md`, правила и конвенции — в `CLAUDE.md` и `packages/cli/CLAUDE.md`, таблица «правило → чем держится» — в `docs/process/rules.md`, готовый запрос фазы 4 — в `docs/handoff/phase-4.md`. История не переносится.

3. **Передача — файл на поток (Q7, Q8).** Поток — линия работы с одной целью (`phase-4`, `git-flow`); файл `docs/handoff/<поток>.md` едет в ветке своего потока, поэтому параллельные ветки не конфликтуют. Последний PR потока удаляет свой файл или заменяет его файлом следующего потока. Форма: заголовок `# <поток>`, затем разделы строго по порядку — **Цель** (1–3 строки), **Готовый запрос** (блок текста), **Открытые вопросы** (к maintainer'у), **Не забыть** (до 5 пунктов — только то, что нельзя вычислить); не больше 60 строк; истории, таблиц решений и состояния нет. Навык `/next-session` становится навыком `handoff`: перезаписывает файл потока.

4. **Состояние вычисляется (Q9).** `scripts/dev/brief.js` (логика — `brief-lib.js` с unit-тестами) только читает локально — без сети, `gh` и `openspec` — и печатает не больше 2 КБ: ветку и worktree сессии, незакоммиченные изменения; все worktree с ветками и файлами `docs/handoff/*.md` в каждом; последний тег, версии CLI и packs; активные Changes (`openspec/changes/*` кроме `archive`) и число открытых задач `- [ ]`; число веток, слитых в `main` и не удалённых; предупреждение по auto-memory (п. 9). Доставка — хук `SessionStart` основной сессии (все источники: `startup`, `resume`, `clear`, `compact` — состояние возвращается и после сжатия) и ручной вызов `node scripts/dev/brief.js`.

5. **Долг — один реестр (Q10).** `docs/backlog.md`, одна таблица `ID | Что | Куда | Источник`; «Куда» — фаза, Change или триггер пересмотра. Префикс ID сохраняет источник (I-, A-, R-, …; строка без источника — `BL-N`). Закрытая строка удаляется: история — в git, закрытие записано в Change или коммите. `architecture.test.ts` читает A-N из реестра.

6. **Стандарт навыка (Q3, Q6).** Все навыки проекта — `.claude/skills/<name>/SKILL.md`; каталог `.claude/commands/` не используется (навык вызывается и через `/<name>`). Frontmatter — только `name` (= каталог), `description` (что делает и «Использовать, когда…»), необязательные `argument-hint`, `disable-model-invocation`. Тело — заголовок и 1–2 строки назначения, затем разделы строго по порядку: **Вход**, **Шаги** (нумерованные, у шага — команда или проверка), **Стоп** (когда остановиться и спросить), **Отчёт**. У линзы и справочника «Шаги» — вопросы или приёмы по порядку применения. Не больше 80 строк; справочный материал — соседним файлом навыка. Норма в навык не пишется: навык ссылается на ADR, шаг может повторять норму как действие. Язык — русский, термины и команды — как есть; английский остаётся за `rule/1` и генерируемым.

7. **`AGENTS.md` (Q12, Q13).** Корневой — не больше 100 строк, разделы: проект одной строкой и карта каталогов; старт сессии (состояние приходит хуком, затем файл передачи своего потока); таблица «задача → навык или инструмент»; жёсткие правила коротким списком, у каждого «держится: <проверка>» и ссылка на ADR; указатель на ADR. `AGENTS.md` — указатель, не источник нормы: норма — в ADR, полная таблица — `docs/process/rules.md`. Конвенции кода (TypeScript ESM, `WarrantError`, `Ctx`, уровни тестов ADR-0025, `writeJsonFile`) — во вложенном `packages/cli/AGENTS.md` (не больше 60 строк): Claude Code подгружает его только при работе в `packages/cli`. Правила — прозой до фазы 4; перенос в `.warrant/local/rules/*.json` (`rule/1`) — строкой в `backlog.md` («Куда: фаза 4», ADR-0022 п. 2).

8. **Состав навыков (Q4, Q14).**

   | Навык | Источник |
   |---|---|
   | `code-search` | как есть, по стандарту п. 6 |
   | `architecture-audit` | ужимается до 80 строк, справочник — соседним файлом |
   | `decision`, `group-done`, `group-stats` | переносятся из `.claude/commands/` |
   | `handoff` | бывший `/next-session`, п. 3 |
   | `software-architect`, `grilling` | переносятся из `~/.claude/skills/` в репозиторий; шаблон ADR — формат `docs/adr/` |
   | `git-flow`, `archive-change` | новые, по этому стандарту, отдельным grilling |
   | `openspec-propose`, `-explore`, `-apply-change`, `-update-change` | OpenSpec (ADR-0015 п. 6), вне стандарта п. 6 |

   Навыки OpenSpec выбираются профилем: `openspec config profile` — custom с `propose`, `explore`, `apply`, `update`, `delivery: skills`. `openspec-archive-change`, `openspec-sync-specs` и `.claude/commands/opsx/**` из репозитория удаляются; закрытие Change — `warrant archive` (ADR-0011 п. 4), процедура — навык `archive-change`. Профиль OpenSpec 1.13.1 — только глобальный: команда настройки машины записывается строкой в `docs/process/rules.md`, а отсутствие файлов держит тест (п. 10). ADR-0015 п. 6 не меняется: файлы по-прежнему принадлежат OpenSpec, выбирается только состав.

9. **auto-memory — только личное (Q5).** В памяти — записи типов `user` и `feedback`: кто пользователь, как с ним работать, предпочтения. Проектные факты и история — всегда в репозитории (п. 1). Индекс `MEMORY.md` — не больше 10 строк. Память вне репозитория, тест её не видит; держит предупреждение `brief.js` (индекс длиннее 10 строк или запись с `type: project`).

10. **Форма — проверкой (правило «о форме — проверкой», R-14…R-16).** Мета-тест `packages/cli/test/unit/meta/dev-context.test.ts`: навыки `.claude/skills/*` кроме `openspec-*` — frontmatter, разделы и их порядок, не больше 80 строк; `.claude/commands/` нет; `openspec-archive-change`, `openspec-sync-specs` нет; `AGENTS.md` — не больше 100 строк, `packages/cli/AGENTS.md` — не больше 60; каждый `docs/handoff/*.md` — разделы п. 3 по порядку, не больше 60 строк, «Не забыть» — до 5 пунктов; `docs/backlog.md` — колонки и уникальные ID; `docs/NEXT-SESSION.md` нет. Правила о решении (что считать потоком, что вычислимо) остаются прозой.

11. **Хуки — уточняет ADR-0029 п. 6.** Команда хука — `node "${CLAUDE_PROJECT_DIR}/scripts/dev/<скрипт>.js" <event>` из белого списка `dev-hooks.test.ts`: `cs-hook.js` — `SubagentStart`, `PreToolUse`, `PostToolUse` (ADR-0029, ADR-0031); `brief.js` — `SessionStart` (п. 4). Пункт ADR-0029 «`SessionStart` не ставится» относится к навыку `code-search` (до субагентов он не доходит); для состояния основной сессии он ставится. Сбой или таймаут `brief.js` сессию не ломает: хук выходит с кодом 0 и пустым выводом.

12. **Порядок (Q15).** Реализация — один process-PR от актуального `main` после ADR-0031 (смержен, PR #26): заморозка и извлечение (п. 2), `backlog.md`, `rules.md`, `docs/handoff/phase-4.md`, `CLAUDE.md` и `packages/cli/CLAUDE.md`, перенос и приведение навыков к стандарту, профиль OpenSpec, `brief.js` и хук, `dev-context.test.ts`, правка `architecture.test.ts` и `dev-hooks.test.ts`. Затем — grilling `git-flow` и `archive-change`, затем аудит и grilling фазы 4 по `docs/handoff/phase-4.md`.

## Consequences

- Старт сессии: `CLAUDE.md` (≤ 100 строк) + состояние хуком (≤ 2 КБ) + файл передачи своего потока (≤ 60 строк) вместо 646 строк NEXT-SESSION. Субагент получает `CLAUDE.md`, указатель `SubagentStart` и промпт координатора; файл передачи ему не нужен.
- Процедуры, ссылающиеся на NEXT-SESSION, переписываются: [coordinator.md](../../.claude/skills/change-coordinate/SKILL.md), навыки `decision` (номер I-N по design.md — без изменений), `group-done`, `handoff`, `architecture-audit` (A-N — в `backlog.md`); память «Decision workflow» (долг — в `backlog.md`, не в NEXT-SESSION).
- Глобальные `~/.claude/skills/software-architect` и `grilling` после переноса удаляются; `grill-me` и `grill-with-docs` (дубли `grilling`) удаляет maintainer — они вне репозитория, но попадают в список навыков каждой сессии.
- `SessionStart` добавляет запуск node (~150–200 мс) и несколько вызовов `git` на старте и после сжатия.
- С фазы 4 (адаптер `claude`, ADR-0023 п. 4, ADR-0029 п. 7) хуки и правила становятся данными local-слоя и выводом `warrant sync`; `CLAUDE.md` ссылается на сгенерированный `AGENTS.md` (ADR-0022). Этот ADR — dev-слой до того момента, не продуктовая норма.

## Alternatives

- **Оставить NEXT-SESSION и ограничить размер** — отвергнуто: не решает конфликтов параллельных потоков и смешения видов знания; бюджет без места для остального только переносит шум.
- **Один файл передачи с разделом на поток** — отвергнуто: параллельные ветки всё равно правят один файл.
- **Передача в описании PR** — отвергнуто: между сессиями одной ветки PR может ещё не быть; текст вне репозитория.
- **Долг в GitHub Issues** — отвергнуто: внешний сервис, `architecture.test.ts` его не прочитает, агентам нужен `gh`.
- **Долг в JSON с проверкой в `validate`** — отвергнуто: продуктовый CLI не знает dev-артефактов (как ADR-0029 п. 6); таблица с мета-тестом проще.
- **Правила сразу в `rule/1` с временным генератором раздела `CLAUDE.md`** — отвергнуто: второй генератор до фазы 4, где `warrant sync` сделает это штатно.
- **Проектные факты в auto-memory** — отвергнуто: вне репозитория, не проверяется, попадает в каждого субагента.
- **Оставить навыки OpenSpec целиком, полагаться на CI (R-16)** — отвергнуто: CI ловит правку main specs, но не обход gates `MERGED → ARCHIVED`.
- **Состояние только ручной командой** — отвергнуто: забытый вызов = сессия без состояния; хук и ручной вызов — один скрипт.
