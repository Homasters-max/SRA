Записать решение по ходу реализации строкой `I-N` в таблицу «Решения по ходу реализации» design.md активного Change.

Вход: `$ARGUMENTS` — текст решения. Пусто — спросить текст у пользователя и остановиться.

**Шаги**

1. **Активный Change — по ветке.**
   ```bash
   git branch --show-current
   ```
   Имя ветки вида `spec/<change>`, `worktree/<change>` или `archive/<change>` → `<change>`. Иначе — сообщить ветку и
   спросить имя Change; не угадывать. Проверить, что существует `openspec/changes/<change>/design.md`
   (`git rev-parse --show-toplevel` — корень, от него все пути).

2. **Следующий номер — по всем design.md, включая архив.**
   ```bash
   grep -ohE '^\| I-[0-9]+ ' openspec/changes/*/design.md openspec/changes/archive/*/design.md | grep -oE '[0-9]+' | sort -n | tail -1
   ```
   `N` = результат (нет строк — `0`); новый номер — `I-<N+1>`. Если в другом worktree идёт параллельная сессия, номер
   мог быть занят там: показать номер пользователю до записи.

3. **Где.** Колонка «Где» — файлы/модули и задача tasks.md, к которым относится решение (например
   `core/gates/verdict.ts`, задача 2.2). Взять из текущей работы; неизвестно — спросить.

4. **Дописать строку** в конец таблицы `## Решения по ходу реализации` в `openspec/changes/<change>/design.md`:
   ```markdown
   | I-<N+1> | <текст решения> | <где> |
   ```
   Только добавление строки: существующие строки и остальной текст design.md не трогать. Символ `|` внутри текста
   экранировать как `\|`. Нет таблицы — сообщить и остановиться.

5. **Проверить** и напечатать итог:
   ```bash
   node packages/cli/dist/bin/warrant.js validate
   ```
   Вывести: `I-<N+1>`, Change, строку целиком, `ok` из `validate`. Не коммитить — коммит делает `/group-done`.
