### P1 — доказательства

**A-28.** `cs grep '["subject"]' --fixed --in packages/cli/src` — 4 символа в 4 файлах (`approvalOf`, `staleReason`,
`mergedCommit`, `specTreeFacts`), каждый сам проверяет `isPlainObject` и тип поля; `cs callers evidenceSubject` —
3 писателя через одну функцию (A-23 держится). Радиус — срезы `runTransition`, `runVerify`, `runGate`, `runArchive`,
`runStatus` (≥ 3). 4c по ADR-0034 п. 12 вводит `subject.tree` и правило `STALE` при несовпадении с деревом
merge-коммита: без общего читателя поле появится в писателе и в 3–5 разборах по отдельности, а семантика «чем
привязана запись» (`commit`, `spec_tree`, `tree`) разойдётся (у `spec_tree` уже своя ветка в `staleReason`).
Справочник: ANT-040 «Missing Abstraction» — ввести тип понятия и перенести в него разбор, рассеянный по вызывающим.

**A-29.** `cs skeleton packages/cli/src/commands/transition.ts` — кроме входа `runTransition` и `forward`: `mergedCommit`
(L102-L128: `readRecords` → `freshest` → `subject.commit` → `isAncestor` → `notMergedHeadReason`), `assertRunRef`
(L201-L217: `attestation.type === "ci"`, сравнение `ref`), `ensureApproval` (L147-L190: `staleReason` +
`countingWaiverIds` для повторного использования, `allocateUlid`, `storeRecord`). `cs deps` файла — 25 импортов (у
остальных команд ≤ 17). ADR-0030 п. 2 держит в `commands/` только опции, выбор checks и `CommandResult`; тест этого не
ловит (правило о содержании, не об импортах). 4c: `ci fetch` (ADR-0034 п. 14) проверяет принадлежность run, head sha,
`subject.tree`, `conclusion` — вторая копия правила «evidence MERGED = один CI-run на head merge», и она будет в
`commands/ci.ts`, если не вынести. Справочник: ANT-074 «Duplicated Logic Masking Functional Coupling» — одна
реализация правила там, где ему место; PAT-008 — одни domain-правила для всех входов (`transition`, `ci`, `ci fetch`),
различаются только use cases.

### 3.4 Наблюдения для spec 4c (не находки)

- **`STALE` — код пред-фильтра, не статус evidence.** `EVIDENCE_STATUSES` (реестр `evidence-status`) — 4 значения;
  `STALE` — `code` находки в `core/gates/prefilter.ts:L99`. ADR-0034 п. 12 говорит «evidence `STALE`»: в spec 4c
  назвать, что это (причина пред-фильтра, как сейчас, или пятый статус — тогда строка реестра `enums`).
- **`ForgePort` — седьмой порт `Ctx`.** Адаптер `gh api` — через `adapters/exec.ts` (как `git-cli.ts`); `FakeForge` —
  в `ProjectBuilder` (ADR-0034 п. 9). Реестр пакетов не меняется, если `gh` зовётся процессом.
- **`warrant ci` и record.** Переход Change — из diff `.warrant/changes/*.json` через `core/record` (владелец переходов —
  `core/record/lifecycle.ts`, реестр `transition`), не разбором JSON в `commands/ci.ts` (повтор §3.4 прошлого аудита).
- **Producer'ы evidence** — `runOneIn` (check), `submitReview` (review), `ensureApproval` (human-approval) — каждый
  зовёт `allocateUlid` → `build…Record` → `manifestVersions` → `storeRecord`; порядок один, владельцы шагов одни. Не
  находка; `ci fetch` кладёт готовые записи — только `storeRecord` (проверка схемой внутри).
- **`bin/warrant.ts`** — 500 строк: `ci` и `ci fetch` доведут его до ~560; порог выноса групп команд — ~600 (прошлый
  аудит).
