# Flow — рабочий дизайн

Доставка Change без рутины человека. Норма — [ADR-0049](../adr/WARRANT-ADR-0049-flow.md). Этот документ — рабочий: таблица стадий и метрики меняются по ходу волн без нового ADR, пока не противоречат ADR-0049 п. 1–7. Источник — стабилизационный аудит 2026-09-29 (`80-flow-dark-factory.md`, вне репозитория).

## 1. Слои

```text
Человек: намерение, решения по риску   ← merge spec- и impl-PR, решения waiver и UNKNOWN
Агент: spec, код, review spec          ← смысловая работа
flow: start · land · status            ← scripts/dev/flow.js, без своего состояния
warrant (судья, пассивен) · git · gh · CI (reusable workflow)
```

## 2. Правила flow

1. **Нет своего состояния.** Стадия выводится из `warrant status --json`, `git` (ветка, worktree, чистота) и `gh` (PR, проверки, merge). Файла состояния flow нет.
2. **Идемпотентность.** Любую команду можно повторить: если PR уже есть, flow его не создаёт; слитый — чистит; удалённую ветку пропускает. Повтор после обрыва продолжает с того же места.
3. **Один вызов — до первой остановки.** Flow останавливается только на:
   - смысловой работе агента (А);
   - решении человека (Ч);
   - красном CI по правилу;
   - неизвестной ситуации.
4. **Только публичный контракт CLI.** `warrant … --json`, без импорта `packages/cli/src/**` и чтения `.warrant/**`. Это держит тест. Нужда залезть внутрь — строка backlog «пробел контракта».
5. **Детерминированный текст.** Коммиты и тела PR собираются из шаблона и артефактов Change (`proposal.md`, `tasks.md`, вывод `verify`), без LLM. Трейлер `Flow: <stage>`.
6. **Не решает за человека.** Нет `--admin`, нет правки защиты, нет активации waiver без ссылки на решение.

## 3. Команды

- `flow start <change|задача>` — worktree и ветка от `origin/main`, после `fetch --prune`; свободный worktree переиспользуется. Для Change префикс ветки выбирается по стадии (`spec/`, `worktree/`, `archive/`).
- `flow land [<change>]` — доводит работу до следующей остановки:
  - для не-Change работы (`docs/`, `process/`, `fix/`): commit → PR → `--auto` → чистка;
  - PR без Change с путями `paths.src` / `paths.tests` не выпускает (ADR-0049 п. 7);
  - на diff с защитой агента `--auto` не ставит (ADR-0049 п. 2).
- `flow status` — все Change и ветки одной таблицей: стадия, что делает машина и **чего ждут от человека** (PR и одно действие). Это входящие решений.

## 4. Таблица стадий

Чистая функция наблюдаемого. **М** — механика, flow делает сам; **А** — остановка на работу агента; **Ч** — остановка на решение человека.

| Наблюдаемое | Действие flow | Кто |
|---|---|---|
| `PROPOSED`, артефакты не закоммичены или не валидны | `openspec validate --strict`, коммит | М; ошибка валидации → А |
| `PROPOSED`, нет review spec | стоп: review субагентом `warrant-reviewer` (`run start … --operation review`) | А |
| `PROPOSED`, review `BLOCKER` | стоп: правка spec | А |
| `PROPOSED`, review `PROVEN` | `classify`, `verify`, `transition SPECIFIED`, push, spec-PR | М |
| spec-PR зелёный, spec не LOW или до волны 3 | стоп в `status`: «слить spec-PR #N» | Ч |
| spec-PR зелёный, LOW, волна 3 (ADR-0049 п. 5) | `--auto` | М |
| waiver ждёт активации или blocking UNKNOWN | стоп: решение maintainer'а комментарием в PR (ссылка) | Ч |
| spec-PR слит, Change `SPECIFIED` | ветка impl, `transition APPROVED --ref`, `IMPLEMENTING`, коммит | М |
| `IMPLEMENTING`, группы `tasks.md` не закрыты | стоп: реализация, группа N | А |
| `IMPLEMENTING`, все группы закрыты | `verify`, `transition VERIFYING`, impl-PR | М |
| impl-PR зелёный | стоп в `status`: «слить impl-PR #N» (merge — решение человека, ADR-0049 п. 2) | Ч |
| impl-PR слит | ветка archive, `ci fetch`, `transition MERGED --ref`, `archive`, PR, `--auto` | М |
| archive-PR слит | чистка worktree и веток, `pull --ff-only`; тег — workflow (ADR-0047 п. 4) | М |
| CI красный: инфраструктура (код 4 / `retryable`) или известный флейк | 1 повтор, затем стоп | М → стоп |
| CI красный по правилу | стоп: сводка находок | А |
| конфликт версий (`package*.json`, lock, golden) | рецепт ADR-0047 п. 6 | М |
| любой другой конфликт или комбинация | стоп: «не знаю — вот наблюдаемое» | А |

## 5. Волны

| Волна | Что | Готово, когда |
|---|---|---|
| 0 | Правила ADR-0049 п. 2–3; `delete_branch_on_merge`; аккаунт бота и Change `identities` | Решения записаны, бот работает под своим логином |
| 1 | `flow.js` v0: `start`, `status`, `land` для не-Change PR и стадии archive; unit-тесты таблицы стадий на fake git/gh, повтор после обрыва на каждом шаге; тест контракта (§2 п. 4) | docs-PR и archive-PR проходят одной командой `flow land`, ноль ручных git-команд |
| 2 | Убрать обходы: ISS-018 (spec-report от `spec_tree`), `transition` без записи при отказе gate, `verify --dry-run`, код выхода инфраструктуры и `retryable` (WS-06), флейк WS-30; WS-01/02 — `release-path` | В навыках 0 строк-обходов |
| 3 | Все стадии §4; судья — WS-03, WS-13, WS-14; floor; LOW без человека (ADR-0049 п. 5–7); детектор на push в `main` (WS-16) | LOW-Change от плана до тега — одно действие человека |
| 4 | Flow в продукт — отдельно от кода судьи, настройки из `warrant.json`; пилот на LATTICE | Следующий Change LATTICE целиком через flow |

## 6. Навык после волны 3 (черновик `fast-mode`)

```text
1. План: цель, границы, риск, 1–3 вопроса. Ответ человека = намерение.
2. flow start <change>.
3. Смысловая работа по остановке flow: spec → review-субагент → код по группам.
4. flow land. Остановка «А» — исправить по сути и снова flow land;
   «Ч» — одна строка из flow status человеку, взять следующую задачу.
5. Стоп: тот же красный CI после двух исправлений; решение, меняющее spec/ADR, — вопрос человеку.
```

`git-start`, `git-land` и механические шаги `change-*-pr` из навыков уходят. Остаётся смысловое: review spec, реализация групп, решения I-N.

## 7. Метрики — без нового состояния

| Метрика | Как считать | Цель |
|---|---|---|
| **Действия человека на Change** (главная) | Merge, review и комментарии maintainer'а в PR Change + ручные коммиты без трейлера `Flow:` | LOW — 1, MEDIUM/HIGH — 2–3 |
| **Простой человека на Change** | Сумма «стоп Ч → действие maintainer'а» по времени событий `gh` | Падает от волны к волне |
| Lead time Change | Первый коммит spec → тег или merge archive-PR | — |
| **Счётчик обходов** | Строки навыков `<!-- workaround: BL-N -->`; `dev-context.test.ts` запрещает обход без ссылки | 0 |
| Ручные git-команды | Коммиты без трейлера `Flow:` на ветках Change | ≈ 0 для механики |
| PR на Change, доля docs-PR | `gh pr list` | 3; доля падает |
| Повторы и остановки flow по типам | Трейлеры и тела PR | Инфраструктура → 0 после WS-30 |
