# Координатор: группы задач — субагентам

Координатор читает spec/design/tasks целиком, пишет субагенту полный промпт, принимает отчёт, сам гоняет проверки `group-done` и проверяет команду руками. Ничего сверх tasks.md: новая потребность — сначала правка tasks/design; отклонение от spec/design — вопросом maintainer'у, принятое — навык `decision` ([ADR-0033](../../../docs/adr/WARRANT-ADR-0033-git-process.md) п. 7). Конвенции кода — `packages/cli/AGENTS.md`.

## Вход

- `<change>`, номер группы `N`; ветка `worktree/<change>` в своём worktree (`git-start where`), дерево чистое, `npm ci` выполнен. Модель субагента — `opus`.

## Шаги

1. **Одна группа — один субагент**, `description` = `<change> group <N>`. Не помещается — продолжение тем же шаблоном, `description` = `<change> group <N> part <k>`, в промпт — сводка предыдущей части (что сделано, какие файлы и символы разобраны, `file:line`).
2. **Промпт** — контекст группы (proposal, design, tasks группы, ADR) называть явно; строка промпта — один логический раздел, по ширине не переносить:
   ```text
   Change <change>, группа <N> tasks.md (openspec/changes/<change>/tasks.md, раздел «## <N>.»). Worktree <путь>, ветка worktree/<change>. Прочитай: <proposal/design/ADR — по группе>. Выполни задачи группы; отклонение от spec — через /decision; в конце — /group-done <N>.
   Не отвечаешь за: openspec/specs/**, задачи других групп, tasks.md вне своей группы, коммиты вне /group-done, push и PR.
   При сбое: проверки /group-done красные 3 раза подряд по одной причине или отказ хука, мешающий законной работе, — стоп и отчёт; не обходить.
   Отчёт (до одной страницы): что сделано по задачам; решения I-N; «Тронутые файлы» — файл и зачем; «Замечено, но не сделано» — всё, что увидел и не стал делать (или «нет»); «Поиск по коду» — как находил места (2–3 примера), где поиск ошибся или не нашёл, пустые или неполные ответы cs и что сделал вместо, отказы хука (или «нет»); «Проверки» — сколько раз /group-done (шаг 2) был красным до зелёного и почему.
   ```
   Указатель на навык `code-search` субагент получает хуком `SubagentStart`; вызов, нарушающий навык, хук `PreToolUse` отклоняет с причиной (ADR-0029 п. 6, ADR-0031). Хуки не сработали (нет `.claude/settings.json` в worktree, `disableAllHooks`) — добавить: «Поиск по коду — строго по навыку code-search: прочитай его до первого обращения к коду».
3. **После группы.** Проверки `group-done` — самому. «Тронутые файлы» вне задач группы — объяснить или откатить; «Замечено, но не сделано» — строкой `docs/backlog.md` или отбросить с причиной в отчёте maintainer'у.
4. **Наблюдение** (ADR-0028 п. 5, ADR-0029 п. 8) — карточка из отчёта: `red_runs` («Проверки»), `helped`, `misled`, `notes` («Поиск по коду»; `misled` — только когда неверный ответ `cs` привёл к ошибке). Запись — навык `group-stats` или:
   ```bash
   node scripts/dev/graft-metrics.js run --change <change> --group <N> [--part <k>] --mode on --red-runs <k> --helped "<…>" --misled "<…>" --notes "<…>"
   ```

## Стоп

- Субагент остановился по «При сбое» — разобрать причину самому, не раздавать группу заново тем же промптом.
- `misled` ≠ `none` или `compliant: false` — сообщить maintainer'у: условие пересмотра ADR-0028, вопрос в бенчмарк ([graft.md](../../../docs/process/graft.md) §5); отказ хука, мешавший законной работе, — повод пересмотра ADR-0031 п. 5.
- Группа требует задачи вне tasks.md — остановиться до правки tasks/design.

## Отчёт

Группа, коммит `group-done`, итог проверок, перенесённое в backlog, карточка наблюдения.
