## Context

Envelope review длиннее ~8 тыс. символов не доходит до `warrant run submit`: bash падает с «unexpected EOF while looking
for matching `'`» (BL-46, второй review `phase-4c`; W-6 подключения LATTICE, 15 851 байт). Замер 2026-09-28:

- Claude Code на Windows запускает `C:\Program Files\Git\bin\bash.exe -c "source <snapshot> && … eval '<команда>' && pwd …"`
  прямо из `claude.exe`, без `cmd.exe`; команда целиком — внутри одного аргумента `-c`.
- Рантайм MSYS2 (Git Bash), запущенный обычным процессом Windows, обрезает этот аргумент на ~8 192 символах: из Node
  `spawnSync(bash, ["-c", "eval '…'"])` — 8 100 символов проходят, 8 170 — та же ошибка; `bin\bash.exe` и `usr\bin\bash.exe`
  одинаково. Предел `CreateProcess` (32 767) ни при чём.
- Обвязка Claude Code — ~450 символов, каждая `'` команды становится `'"'"'`: на команду остаётся ~7,7 тыс. символов (символов,
  не байт). На Linux и macOS предел аргумента — от 128 КБ.

Ошибка возникает до запуска команды и ничего не говорит о причине; агент повторяет попытку или урезает текст.

## Decision

1. **Длинный текст — файлом.** Сообщение коммита, тело PR, envelope, JSON и любой многострочный текст, который может
   превысить предел, пишется файлом (инструмент `Write`, scratchpad сессии) и передаётся путём: `git commit -F`,
   `gh pr create --body-file`, `warrant run submit --file`. Heredoc в команде — только для короткого текста. Это правило о
   форме: его держит механизм (п. 2), а не проза.
2. **`git-hook.js`, правило `long-command`** (уточняет [ADR-0033](WARRANT-ADR-0033-git-process.md) п. 9). На `win32`
   `PreToolUse` Bash основной сессии и субагентов с «стоимостью» команды больше 7 000 — длина плюс 4 на каждую `'` — даёт
   `deny` с причиной (предел Git Bash) и выходом (файл и флаг пути). Хук получает команду из stdin целиком, до обрезки.
   Порог — с запасом ~700 символов до замеренного предела. PowerShell и другие платформы правило не трогает.
3. **Продукт.** Тот же отказ нужен агенту подключённого проекта на Windows — `warrant guard --frontend claude` (строка
   backlog, фаза 5). Сдача review файлом — [ADR-0042](WARRANT-ADR-0042-lattice-fixes.md) п. 4.

## Consequences

- ADR-0033 п. 9 — заметка `amended_by`; `dev-hooks.test.ts` — правило `long-command` в закреплённом наборе.
- `docs/process/rules.md` — строка правила; `CLAUDE.md` — жёсткое правило.
- Навык `change-spec-pr` шаг 3: субагент сдаёт envelope `--file`; до выпуска `lattice-fixes` (CLI 0.8.1) старый субагент
  сдаёт heredoc — envelope не длиннее 6 000 символов, полный текст находок — в тело PR.
- Память сессий — `windows-bash-command-limit`.

## Alternatives

- **Прописать предел только в навыках и памяти** — отвергнуто: правило о форме без проверки (ADR-0032, INV-04).
- **Обходить предел частями (несколько команд `cat >> file`)** — отвергнуто: `Write` проще и не зависит от кавычек.
- **Искать причину в Claude Code и ждать исправления** — не решение для нас: предел в рантайме Git Bash; отказ хука
  ставит понятную причину на место непонятной.
