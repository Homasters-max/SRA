Записать группу `N` активного Change: метрики поиска по коду из транскрипта субагента плюс карточка координатора
(наблюдение ADR-0028 п. 5). Процесс — `docs/process/coordinator.md` §3.

Вход: `$ARGUMENTS` — номер группы `N`. Пусто — спросить и остановиться.

**Шаги**

1. `<change>` — из ветки `worktree/<change>`; иначе спросить.

2. **Карточка** — по отчёту субагента (разделы «Поиск по коду» и «Проверки»):
   - `red_runs` — сколько раз проверки `/group-done` (шаг 2) были красными до зелёного;
   - `helped` — `yes` / `partly` / `no`;
   - `misled` — `none`, или что именно `cs` ответил неверно и к какой ошибке это привело;
   - `notes` — неполные, но безвредные ответы; почему группа нетипична (одни документы и т. п.).
   Сомнение в `red_runs` или `misled` — спросить пользователя.

3. **Запись.**
   ```bash
   node scripts/dev/graft-metrics.js run --change <change> --group <N> --mode on --red-runs <k> --helped <…> --misled "<…>" --notes "<…>"
   ```
   Несколько транскриптов под одно описание: группу делили — записать каждую часть с `--part k --agent <путь>`;
   группу перезапускали — последний завершённый, `--agent <путь>`.

4. **Итог.** Одной строкой: `ingest.explore_bytes`, `tokens.total`, `tool_calls.total`, `graft`, `deviations`
   (число), `compliant`, `red_runs`. `misled` ≠ `none` — условие пересмотра ADR-0028: сообщить пользователю и
   предложить вопрос в бенчмарк (`scripts/dev/bench/code-search.json`). `compliant: false` — сообщить: агент не
   следовал навыку `code-search`. Файл записи — в `.git`, коммитить нечего.
