# Режим и список шагов

Maintainer должен с первого взгляда видеть, где задача и чего она ждёт от него. Режим называет, нужен ли процесс Change; список показывает шаги и их состояние.

## Вход

- Задача maintainer'а. Режим задан словом «разработка: …» или «лайт: …»; не задан — выбрать по шагу 1.
- Состояние: `node scripts/dev/brief.js`, `warrant status <change>` активного Change.

## Шаги

1. **Режим.** Первой строкой ответа — режим и почему:
   - 🛠 **Разработка** — затронуты `packages/**`, `openspec/**`, `.warrant/**`, `packs/**`, `sra/**`, `.github/workflows/**`: Change из трёх PR (`change-spec-pr` → `change-impl-pr` → `change-archive-pr`);
   - 🪶 **Лайт** — файлы, заметки, доки, навыки, настройки, игнор: без Change и без worktree, если коммит не нужен (игнор только для себя — `.git/info/exclude`); нужен коммит — docs- или process-PR (`git-land`).

   Сомнение — 🛠. Лайт, задевший пути разработки, — стоп и переход в 🛠 с объяснением.
2. **Список** — блоком `text`, сразу при старте:
   ```text
   🛠 Разработка · Change <change>
   ✅ 1  💬 Идея и grilling                      — grilling
   ✅ 2  📝 Доки Change: proposal, design, tasks — openspec-propose
   ✅ 3  👤 Ты проверил и допилил
   🔄 4  🔍 Ревью spec → SPECIFIED              — change-spec-pr
   ⏭️ 5  👤 Merge spec-PR в браузере
   ⬜ 6  🛠 Реализация: группы tasks.md          — change-impl-pr
   ⬜ 7  🔍 Ревью реализации → VERIFYING         — review-impl
   ⬜ 8  👤 Merge impl-PR (с 0.9.0 — 🤖 агент)
   ⬜ 9  📦 Archive-PR — сливает бот             — change-archive-pr
   ⬜ 10 🧹 Чистка и передача                    — git-land, handoff
   ```
   Лайт — только свои шаги, последняя строка — «PR не нужен» или ссылка на PR:
   ```text
   🪶 Лайт · <задача>
   ✅ 1  <что сделано>
   🔄 2  <что делается>
   ```
   Отметки: ✅ готово · 🔄 в работе · ⏭️ следующий · ⬜ впереди · 👤 ждёт maintainer'а. У строки 👤 — полная ссылка на PR и что нажать.
3. **Обновление.** Список целиком — после каждого закрытого шага, на «где мы?» и в конце ответа, который ждёт maintainer'а; одна строка 🔄 — текущая. Шаг 1 после grilling — вопрос «оформить Change?», не ожидание слова «сделай доки».
4. **Несколько задач** — список на каждую, по порядку; задача ждёт 👤 — работа идёт по следующей.

## Стоп

- Режим не ясен и задача меняет поставляемое или норму — спросить одной строкой, не начинать.
- Лайт требует правки путей разработки — не делать её в лайте: перейти в 🛠 и показать новый список.

## Отчёт

Список шагов текущей задачи; строка 👤 — ссылка и действие maintainer'а.
