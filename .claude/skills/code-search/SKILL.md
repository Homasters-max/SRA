# Поиск по коду через граф

Порядок принят [ADR-0028](../../../docs/adr/WARRANT-ADR-0028-graft-adoption.md) по итогам эксперимента
([отчёт](../../../docs/process/graft-report.md)). Правила 1–6 обязательны.

Код WARRANT (`packages/**`, `scripts/**` — `.ts`, `.js`) проиндексирован графом: узлы — функции, типы, файлы;
рёбра — кто кого вызывает и импортирует. Запрос к графу стоит сотни токенов и не пропускает связи; чтение исходников
целиком стоит тысячи и пропускает. Инструмент — `cs`: `node scripts/dev/cs.js <команда>` из корня worktree (из
подкаталога — `node "$(git rev-parse --show-toplevel)/scripts/dev/cs.js" <команда>`). Индекс строится и обновляется
сам. В свежем worktree нужен `npm ci` (обёртка импортирует `cross-spawn`).

Не индексируются и ищутся обычными средствами (grep, Read) без ограничений: документы (`docs/**`, `openspec/**`,
`*.md`), данные и конфиги (`*.json`, `*.yaml`, локи, `package.json`), `node_modules` и исходники других пакетов
(OpenSpec, vitest).

## Правила

1. **Код ищешь только через `cs`.** Не использовать для кода: инструмент Grep по `packages/`, `scripts/`, `*.ts`;
   `grep -r`, `rg`, `git grep` по коду; `graft` напрямую. Список файлов (`ls`, `find -name`, Glob) — можно.
2. **Код читаешь только диапазонами.** Сначала `cs skeleton <файл>` (или `file:line` из ответа `cs`), затем Read с
   `offset`/`limit` (или `sed -n a,bp`) — только нужные строки. Файл кода целиком (Read без `offset`/`limit`, `cat`)
   не читать, даже короткий: у короткого диапазон `1..N` из skeleton.
3. **Перед изменением сигнатуры, переименованием, удалением, сменой поведения экспорта** — `cs callers <символ> -d 2`;
   перед правкой нескольких файлов — `cs callers <символ> -d all`. Каждое место из ответа — учесть в правке или явно
   отметить, почему не затронуто. Граф связывает одноимённые символы по имени и может дать ложное ребро (локальная
   переменная `forward` ≠ функция `forward`): место, которое не сходится, проверь `cs grep` и диапазоном кода.
4. **Один вызов — один ответ.** Выбери команду по таблице, действуй по ответу. Не переспрашивай тот же вопрос другими
   словами: слабый ответ `ask` — переключись на `grep` / `skeleton` / `callers`. Ответ `ask` «такого в коде нет»
   (только нерелевантные совпадения) — полноценный ответ: проверь одним `cs grep` по ключевому слову и действуй.
5. **Не обрезай вывод `cs`** (`| head`, `| tail`): он уже ограничен и сообщает, что отброшено.
6. **`cs` вернул код 2 или 3** — не обходить: код 2 — поправь команду; код 3 — остановись и сообщи. Пусто после двух
   разных команд `cs` по одному вопросу (`grep` с ослабленным шаблоном и `ask`) — тогда можно обычный поиск по этому
   вопросу, с пометкой в отчёте.

## Команды

| Задача | Команда |
|---|---|
| Где поведение X (место неизвестно) | `cs ask "<где X>" --source` (`--in <путь>`, `-n N`) |
| Все вхождения символа или литерала | `cs grep "<короткое имя>"`; не нашёл — ослабь шаблон (голое имя без сигнатуры), `-i`, `--fixed`; `--in <путь>` — сузить |
| API файла | `cs skeleton <файл>` — функции, типы, методы со строками; экспортированные константы — `cs grep "export const" --in <файл>` |
| Кто вызывает / что сломается | `cs callers <символ> -d 2`; от чего зависит — `--direction out`; весь связный кусок — `-d all` |
| Незнакомая область | `cs map` — один раз, дальше по названным узлам |

## Сценарии

| Ты… | Путь |
|---|---|
| Знаешь символ, который меняешь | `cs grep "<символ>"` → правка по `file:line`; сигнатура меняется — сначала `callers -d 2` |
| Не знаешь, где это | `cs ask "<поведение>" --source` → `skeleton` нужного файла → Read диапазона |
| Переносишь вызовы за порт | `cs grep "<вызов>"` (все места) → `cs callers <функция> -d all` → правки по списку |
| Разбираешь падение теста | `cs ask "<симптом>" --source` → `callers` подозреваемого |
| Пишешь тест на функцию | `cs skeleton <файл>` + `cs callers <функция>` |

Запрещено всегда (ADR-0026 п. 2): `graft init`, `upgrade`, `mcp`, `brain`, флаги `--deep`, `--lsp`; обёртка их не
пропускает.
