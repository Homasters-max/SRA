# Оркестрация агентов — справочник линзы `software-architect`

Для проектирования процессов с агентами: dev-процесс WARRANT (координатор, субагенты, навыки git и Change) и фабрика
SEF (попытки, `landing`, approval). Источник — агент multi-agent-systems-architect каталога agency-agents,
адаптирован ([ADR-0033](../../../docs/adr/WARRANT-ADR-0033-git-process.md) п. 8). Норма — в ADR; здесь — вопросы.

## Роль агента

У каждой роли — пять полей; пустое поле — вопрос к дизайну, не умолчание:

| Поле | Вопрос | Пример WARRANT |
|---|---|---|
| Отвечает за | какой результат и в какой форме | группа tasks.md, коммит `group-done` |
| Не отвечает за | что трогать нельзя, даже если видно | `openspec/specs/**`, чужие группы, push |
| Инструменты | минимум для роли | `reviewer` — без `Write`/`Edit` |
| При сбое | когда остановиться и что вернуть | 3 красных прогона подряд — стоп и отчёт |
| Бюджет | размер отчёта, время, число попыток | отчёт до страницы |

## Типы сбоев

| Сбой | Признак | Защита |
|---|---|---|
| Тихий | агент «успешно» сделал не то; отчёт гладкий | проверка результата вне агента: тесты, `validate`, сверка со spec (`review-impl`) |
| Частичный | сделана часть, состояние между шагами | шаги, которые можно повторить; переход record — отдельным коммитом; `STALE` виден в `status` |
| Каскадный | ошибка одного агента — вход следующего | граница с проверкой между агентами: координатор сам гоняет проверки группы |
| Петля | повтор одного и того же исправления | счётчик попыток по одному сбою, стоп после второй (`git-land`, ci.md) |
| Расползание объёма | агент делает больше задачи | «тронутые файлы» и «замечено, но не сделано» в отчёте; `scope-valid` |
| Обход проверки | агент отключает тест или ослабляет правило, чтобы пройти | хук `deny` по входу вызова; «обход запрещён» в роли |

## Где проверка человеком

Человек — там, где действие необратимо или радиус поражения выходит за ветку (ADR-0033 п. 1):

| Действие | Обратимо? | Радиус | Решение |
|---|---|---|---|
| коммит, ветка, worktree, PR | да | ветка | агент сам |
| merge в `main` | с трудом (revert) | все сессии | человек решает («merge #N»), агент выполняет |
| принятие риска (waiver) | да, но меняет доверие | Change | человек (`--activate --by`) |
| force push, удаление неслитого | нет | общая история | только человек вручную |
| настройки репозитория, права агента | да | все агенты | только человек |

Вопрос дизайну: где в предлагаемом процессе стоит каждое необратимое действие и кто его подтверждает.
