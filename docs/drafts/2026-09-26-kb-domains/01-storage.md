# Где живут домены и кто их обновляет

## Проблема

- Домены (`lifecycle.json`, `kernel.json`), формат и стенд лежат в `.kb-search/` основного checkout — вне git. Агенты в worktree видят их только с `--root <основной checkout>`; правки не проходят ревью и тесты.
- Домен — производный слой: после правки документа или кода ссылки units устаревают (строки, символы), а перенарезки по событию нет.
- `docs/integrations/` — контракты с LATTICE и другими компонентами SEF; по `AGENTS.md` их не трогаем, но 7 файлов сейчас в общем индексе поиска WARRANT.

## Идея

- Уровни: **компонент SEF** (WARRANT, LATTICE, SRA, JEV — ADR-0008) → **домен** (lifecycle, kernel, policy и packs, Run и skills, интеграции, процесс разработки, планирование) → **unit**.
- Домены — в репозитории (например `docs/domains/<domain>.json` или `.warrant-dev/domains/`), генерируемые, проверка формы — тестом (как `dev-context.test.ts`); стенд и журналы — локально.
- `integrations` — домен только для чтения: нормы принадлежат другому компоненту, противоречия — его владельцу.
- Обновление: перенарезка изменённых источников — в archive-PR Change (нормы меняются только там, R-16) и проверка устаревания в `hygiene.js`.

## Вопросы для grilling

1. Домены в репозитории или локально? Рекомендация: в репозитории — один источник для всех агентов и worktree; новый каталог — правка `structure.test.ts` и ADR (ADR-0033 п. 13).
2. Каталог: `docs/domains/` (документы) или отдельный машинный каталог? Рекомендация: рядом с документами, JSON с `$schema` `warrant://domain/1`? — или свой URI навыка, раз это инструмент разработки, а не продукт.
3. Список доменов и границы. Рекомендация: начать с 7 из «Идеи», границу проверять долей перекрёстных ссылок.
4. `docs/integrations` (контракты LATTICE, SRA, JEV): домен только для чтения или исключить из индекса WARRANT? Рекомендация: домен только для чтения — модель сущностей опирается на контракт LATTICE (02), вопросы на стыке задают, ответ должен находиться.
5. Кто и когда перенарезает домен? Рекомендация: навык (новый шаг `change-archive-pr` для доменов Change) + `hygiene.js` помечает устаревшее; полная перенарезка — вручную по решению.
6. Навык `kb-search` вне репозитория — оставить так или положить нужную часть (формат, резолвер, `--by-code`) в `scripts/dev/`? Рекомендация: формат и проверки — в репозиторий, поиск и Jev — навык.

## Вне объёма

- Домены LATTICE, SRA, JEV — их владельцы.
- UI поиска (`kb-ui`).
