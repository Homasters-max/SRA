## Context

[02 §3](../02-vocabulary.md): `REQ-AREA-NNN`, `EVID-000921`, `RUN-000417` — счётчики; «ID выдаёт CLI»,
«никогда не меняется», «не переиспользуется». Два агента в двух worktree вызовут `warrant id REQ ING` и оба получат
`REQ-ING-007`; при merge — коллизия, а переименовать нельзя по определению. `EVID` / `RUN` создаются на каждом
прогоне, счётчик здесь ломается гарантированно. Реестр выданных ID в файле конфликтует при merge так же, как счётчик.

## Decision

1. **Spec-уровень (`REQ`, `SCN`, `TASK`, `UNK`, `ASM`) — `PREFIX-AREA-NNN`**, читаемость важна людям и LLM.
   ID становится **immutable с момента `MERGED`** соответствующего spec-PR. До этого CLI при коллизии с base-веткой
   перенумеровывает внутри Change командой `warrant id renumber <old> <new>`: переписываются ссылки только внутри
   каталога Change и его тестов; команда отказывает, если новый ID уже есть на base.
2. **Сквозные объекты (`EVID`, `RUN`) — `PREFIX-<ULID>`**: `EVID-01J8Z3M5K9X7Q2R4T6V8W0Y1A3`. Их никто не набирает
   руками; ULID упорядочен по времени и не требует координации.
3. **`WAV-<year>-NNN` остаётся**: waivers редки и создаются человеком на `main`.
4. **Без файла-реестра.** Следующий NNN = max по `main` (`openspec/specs/**` + `openspec/changes/**`, включая
   archive) + 1. Удалённые требования остаются в archive, поэтому «не переиспользуется» соблюдается сканированием.
   `ids-valid` в CI сравнивает с base-веткой.
5. **AREA — реестр `.warrant/local/areas.json`**: `{ "CUS": { "capability": "customer-search" } }`, 1:1 с каталогом
   `openspec/specs/<capability>/`. Неизвестная AREA — ошибка `ids-valid`.
6. **Имя Change не переиспользуется.** Создание Change отказывает, если имя есть в `.warrant/changes/`
   или `openspec/changes/archive/*-<name>`.
7. **Размещение `<!-- id: … -->`** (spike S1, OpenSpec 1.13.1): строго под своим заголовком уровня 3 / 4; после
   комментария обязательно непустое тело. Комментарий над заголовком приклеивается к предыдущему требованию;
   комментарий между `## ADDED Requirements` и первым `### Requirement:` при archive теряется; незакрытый `<!--`
   вырезает всё после себя. `ids-valid` проверяет позицию и наличие тела.

## Consequences

- ADR-0004 переведён в `ACCEPTED`.
- Формат в [02 §3](../02-vocabulary.md) и все примеры `EVID-000921` / `RUN-000417` заменены на ULID.
- Коллизии NNN возможны только в одной AREA в параллельных Changes; в MVP (один агент) не возникают, но правило
  зафиксировано до фазы 7 (orchestration).

## Alternatives

- **Случайный суффикс для spec-уровня** (`REQ-ING-7K3Q`) — отвергнуто: теряется читаемость и порядок, а коллизии
  NNN решаются перенумерацией до `MERGED`.
- **Резервирование на main отдельным коммитом** — отвергнуто: требует сети и координации на каждый ID.
- **Реестр `.warrant/ids.json`** — отвергнуто: конфликтует при merge так же, как счётчик.
