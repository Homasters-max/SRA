# Поиск по коду через граф

Порядок принят [ADR-0028](../../../docs/adr/WARRANT-ADR-0028-graft-adoption.md), уточнён по итогам аудита
[ADR-0029](../../../docs/adr/WARRANT-ADR-0029-graft-audit-dev-hooks.md) ([отчёт](../../../docs/process/graft-audit.md)).
Правила 1–6 обязательны. У субагента вызов, нарушающий правила 1, 2 или 5, хук отклоняет до выполнения
([ADR-0031](../../../docs/adr/WARRANT-ADR-0031-pretooluse-deny.md)): текст отказа говорит, что сделать вместо, — сделай
это, не обходи отказ скриптом или другим инструментом.

Код WARRANT (`packages/**`, `scripts/**` — `.ts`, `.js` рабочего дерева репозитория, любого его worktree) проиндексирован
графом: узлы — функции, методы, типы, файлы;
рёбра — вызовы и импорты. Инструмент — `cs`: `node scripts/dev/cs.js <команда>` из корня worktree (из подкаталога —
`node "$(git rev-parse --show-toplevel)/scripts/dev/cs.js" <команда>`; `--in` и путь файла считаются от текущего
каталога). Индекс строится и обновляется сам.

**Чего граф не видит** (аудит против компилятора TypeScript): вызовов через порты и интерфейсы (`ctx.git.head()`,
`ctx.checks.run()`); вызовов из другого файла, если имя определено в нескольких файлах; вызовов методов у переменной
без известного типа и в цепочках (`project().withChange()`). Константы модуля — не узлы. Поэтому `callers` —
нижняя граница, а список правок даёт `impact`.

Не индексируются и ищутся обычными средствами (grep, Read) без ограничений: документы (`docs/**`, `openspec/**`,
`*.md`), данные и конфиги (`*.json`, `*.yaml`, локи, `package.json`), `node_modules` и исходники других пакетов, а
также `.ts`/`.js` вне `packages/`, `scripts/` дерева — свои скрипты в scratchpad, temp, другие репозитории.

## Правила

1. **Код ищешь только через `cs`.** Не использовать для кода: инструмент Grep по `packages/`, `scripts/`, `*.ts`
   (и Grep без пути — он ищет по всему репозиторию); `grep -r`, `rg`, `git grep`, `Select-String` по коду; `graft`
   напрямую. Список файлов (`ls`, `find -name`, Glob) — можно.
2. **Код читаешь только диапазонами.** Сначала `cs skeleton <файл>` (или `file:line` из ответа `cs`), затем Read с
   `offset`/`limit` (или `sed -n a,bp`) — только нужные строки. Диапазон, покрывающий весь файл (`offset=1` с
   `limit` не меньше длины, `sed -n 1,Np`, `head -N`), — это чтение целиком; целиком можно только файлы до 40 строк.
   `skeleton` ответил «no definitions indexed» (скрипт, одни константы) — `cs grep "^(export )?(const|let)" --in
   <файл>`, затем диапазон.
3. **Перед изменением сигнатуры, переименованием, удалением, сменой поведения экспорта — `cs impact <символ>`.**
   Это список правок: вызовы по графу и по имени, объемлющий символ, строка вызова. Каждое место — учесть в правке
   или явно отметить, почему не затронуто. Метка `[graph]` (ребро есть, строки вызова нет) и `local?` (в той же
   функции есть одноимённая переменная) — кандидаты в ложное ребро: проверь диапазоном. Если `impact` перечисляет
   несколько определений имени — отнеси каждое место к своему. `cs callers <символ> -d 2` / `-d all` — для цепочек
   («что сломается дальше»), но не как список правок; строка под вызывающим в `callers` — не обязательно вызов.
4. **Один вызов — один ответ.** Выбери команду по таблице, действуй по ответу. Не переспрашивай тот же вопрос другими
   словами. `ask` — лексический поиск по словам: для понятий («где переходы lifecycle») он слаб — ищи по имени,
   константе или литералу через `cs grep`. Ответ `ask` с пометкой `(empty)`, или `(lexical)` без ключевых слов
   вопроса в найденных именах, — «такого нет»: проверь одним `cs grep` и действуй.
5. **Не обрезай вывод `cs`** (`| head`, `| tail`): он уже ограничен и сообщает, что отброшено. Для разбора
   программой — `--json` (без ограничений), а не парсинг текста.
6. **`cs` вернул код 2 или 3** — не обходить: код 2 — поправь команду (текст ошибки говорит как); код 3 — остановись и
   сообщи. Код 1 — ответ graft «не нашёл» (нет символа, пустой `--in`, неверный regex). Пусто после двух разных
   команд `cs` по одному вопросу (`grep` с ослабленным шаблоном и `ask`) — тогда можно обычный поиск по этому
   вопросу, с пометкой в отчёте.

## Команды

| Задача | Команда |
|---|---|
| Что обновить, если меняю X | `cs impact <символ>` (`Type.method` — только вызовы метода; `--in <путь>`). Константа, тип, метод интерфейса — не функция графа: `impact` ищет каждое вхождение имени (`match: word`) |
| Где поведение X (место неизвестно) | `cs ask "<где X>" --source` (`--in <путь>`, `-n N`) |
| Все вхождения символа или литерала | `cs grep "<шаблон>"` — JS-regex: «или» пиши `a|b` (не `a\|b`), `(` экранируй; литерал — `--fixed`; `-i`; `--in <путь>`. Не нашёл — ослабь шаблон (голое имя) |
| API файла | `cs skeleton <файл>` — функции, типы, методы со строками; константы — `cs grep "export const" --in <файл>` |
| Кто вызывает / цепочка | `cs callers <символ> -d 2`; от чего зависит — `--direction out`; сценарий целиком — `--direction out -d all` |
| Импорты файла, кто его импортирует | `cs deps <файл>` (`type-only` — только `import type`) |
| Граф модулей, связность | `cs deps <каталог> --level N` — рёбра модулей, Ca / Ce / нестабильность; `--external`. Модули-файлы `core/*.ts` в `--level` входят в `core`; границы модулей — `packages/cli/test/unit/meta/architecture.json` (ADR-0030) |
| Циклы импортов | `cs deps --cycles --in <путь>`; без `import type` — `--runtime`; модулей — `cs deps <каталог> --level N --cycles` |
| Одноимённые определения | `cs dups --in <путь>` (`--min N`) — имена, у которых граф теряет вызовы из других файлов |
| Незнакомая область | `cs map` — один раз, дальше по названным узлам |

`--json` — у всех команд, кроме `version`.

## Сценарии

| Ты… | Путь |
|---|---|
| Меняешь сигнатуру или поведение символа | `cs impact <символ>` → правки по списку → `callers -d 2`, если важна цепочка дальше |
| Не знаешь, где это | `cs ask "<поведение>" --source` → `skeleton` нужного файла → Read диапазона |
| Переносишь вызовы за порт | `cs impact <функция>` (все места) → правки по списку |
| Разбираешь падение теста | `cs ask "<симптом>" --source` → `impact` / `callers` подозреваемого |
| Пишешь тест на функцию | `cs skeleton <файл>` + `cs impact <функция>` |
| Оцениваешь архитектуру | `cs map` → `cs deps <каталог> --level N` → `--cycles --runtime` → `cs dups` → срез сценария `callers <вход> --direction out -d all --json` |

Запрещено всегда (ADR-0026 п. 2): `graft init`, `upgrade`, `mcp`, `brain`, флаги `--deep`, `--lsp`, каталог
позиционным аргументом; обёртка их не пропускает. Хуки разработки ([ADR-0029](../../../docs/adr/WARRANT-ADR-0029-graft-audit-dev-hooks.md)
п. 6, [ADR-0031](../../../docs/adr/WARRANT-ADR-0031-pretooluse-deny.md)) держат этот порядок у субагентов сами:
`PreToolUse` отклоняет нарушение, видимое по вызову; `PostToolUse` подсказывает, если нарушение видно только по выводу.
Отказ хука, мешающий законной работе, — в отчёт (раздел «Поиск по коду»), не обход.
