> Итог — [ADR-0028](WARRANT-ADR-0028-graft-adoption.md): бенчмарк п. 4 дал `accept`; алгоритм вернулся в навык
> `.claude/skills/code-search` (вызываемый моделью) — п. 2 про слепоту больше не применяется; бенчмарк остаётся для
> регрессии при обновлении Graft.

## Context

Первый полевой прогон [ADR-0026](WARRANT-ADR-0026-graft-experiment.md) на Change `test-levels` (6 групп, `[A]` —
1, 3, 5; `[B]` — 2, 4, 6) показал:

- **Вреда нет:** ни одного `misled`, отказа `cs` с кодом 3, вызова graft в обход обёртки или грязного дерева.
  Качественно помогает: `callers -d 2` перед сменой сигнатуры (g3), `skeleton` + `callers` для безопасного удаления
  хелпера (g5).
- **Сравнение по полю невалидно:** группы различаются по объёму в ~100 раз (105…9 911 строк диффа), метка совпала с
  характером задачи. Медиана токенов `[A]` на 57 % ниже, на строку диффа — наоборот.
- **Детектор отступлений ошибался:** `compliant: false` у g1 — почти целиком ложные срабатывания (heredoc-запись
  файла, `sed -i` в `package.json`, поиск по `node_modules` и JSON, `find`-список).
- **Слепота нарушена:** индекс памяти `MEMORY.md` загружается в каждого субагента — строка об эксперименте в нём
  была; субагент `[B]` g2 по этой подсказке выполнил `ls .claude/skills` и прочитал `code-search/SKILL.md`.
  `disable-model-invocation` не скрывает файл в репозитории. Зонд этого не поймал: память он не проверял. Поведение
  `[B]` не изменилось — ни одного вызова `cs`.
- **Запись g5** — пять субагентов, склеенный транскрипт в scratchpad чужой сессии.
- Агенты назвали слабые места алгоритма: JSON-литералы и `node_modules` не индексируются; `skeleton` не показывает
  экспортированные константы; `ask` слаб на общих понятиях.

## Decision

1. **Записи `test-levels` засчитываются** с пометкой `blind-leak`. Запись `[B]` засчитывается, только если в ней нет
   вызовов `cs` и `graft` (иначе — нарушение).
2. **Слепота без памяти и навыка.** Индекс памяти проекта не содержит ничего о процессе раздачи групп.
   `.claude/skills/code-search/` удалён: алгоритм — [docs/process/code-search.md](../process/code-search.md),
   координатор вставляет его текст в промпт группы `[A]`. Зонд перечисляет всё из system-reminder, включая память;
   ответ проверяется механически на список запрещённых слов ([coordinator.md](../../.claude/skills/change-coordinate/SKILL.md) §1).
3. **Детектор отступлений** не считает: запись файлов (heredoc, `sed -i`, перенаправление), JSON / конфиги / локи /
   документы, `node_modules`, список файлов (`ls`, `find`, Glob), фильтр вывода после `|`; первый аргумент
   `grep` — шаблон, а не путь. Реальные команды `test-levels` — unit-тесты. Записи пересчитаны (`rescore`): `[A]` —
   1, 3, 3 отступления (все `compliant`), `[B]` — 25–27 в больших группах.
4. **Основной замер — парный бенчмарк.** `scripts/dev/bench/code-search.json`: 8 вопросов «найди все места…» из групп
   `test-levels`, эталон — по AST TypeScript на родительском коммите группы (без graft). Каждый вопрос — субагент
   `[A]` и `[B]` на одном коммите, только чтение; оценка — `scripts/dev/bench-score.js` (recall, precision,
   прочитанные байты). **Accept:** все вопросы в обеих метках, медиана отношения `explore_bytes[A] / explore_bytes[B]`
   ≤ 0,8, средний recall `[A]` не ниже `[B]`, `cs` в `[B]` не вызывался. Поле (группы задач) — справочно, та же
   метрика.
5. **Метрики и записи.** Основная — байты результатов исследующих вызовов (`ingest.explore_bytes`) и они же до первой
   правки; токены — вторичны. Одна группа — один субагент; иначе части `--part k`, `report` суммирует. `run` копирует
   транскрипт в `graft-lab/transcripts/`; `rescore` пересчитывает записи текущими метриками.
6. **Алгоритм:** явно разрешён обычный поиск по JSON, конфигам, `node_modules` и чужим пакетам; экспортированные
   константы — `cs grep "export const" --in <файл>`; ответ `ask` «такого нет» — ответ, а не повод переспрашивать.
   Правки текста алгоритма — только между прогонами.

## Consequences

- ADR-0026 п. 4 (навык `code-search` в `.claude/skills`), п. 5 (зонд без памяти), п. 6 (порог по токенам или tool
  calls по полю) уточнены пп. 2, 4 этого ADR; остальное в силе.
- `graft-metrics` — формат записи `graft-run/2` (`ingest`, `part`), отчёт `graft-report/2`; бенчмарк —
  `code-search-bench-result/1`, `code-search-bench-report/1`. Всё — в `scripts/dev/`, вне пакета.
- Worktree бенчмарка `SRA-bench-<sha>` (detached, `npm ci`, индекс заранее) — временные, удаляются после отчёта.
- Поиск по имени без разрешения областей видимости даёт ложные рёбра — и у наивного скрипта, и у graft
  (`callers evaluateGates -d all` проходит через локальную переменную `forward` в `runCommand`). Эталон строится по
  AST с проверкой каждого ребра; правило 3 алгоритма (проверить каждое место из `callers`) остаётся обязательным.

## Alternatives

- **Продолжать только поле** — отвергнуто: смешение по размеру задач не уходит, до вывода — десятки групп.
- **Переиграть группы целиком в обеих метках** — отвергнуто: дорого (десятки млн токенов на группу), а поиск — лишь
  часть работы группы.
- **Оставить навык в `.claude/skills`, спрятать описание** — отвергнуто: файл находится листингом каталога.
- **Не засчитывать записи с утечкой** — отвергнуто: утечка изменила знание, но не поведение (`cs` в `[B]` — 0).
