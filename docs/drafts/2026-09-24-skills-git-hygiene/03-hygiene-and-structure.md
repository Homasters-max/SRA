# 03 — структура каталогов и имён, навык гигиены

## Проблема

Структура репозитория ни в одном месте не описана целиком: по частям она есть в ADR-0013 (monorepo: `docs/`,
`packages/cli/`, `packs/core-sdd/`, `sra/skills/`, `lattice/`), ADR-0015, ADR-0026 и ADR-0032. Проверяется частично:
`package-contents.test.ts`, `architecture.json`, `dev-hooks.test.ts`, `validate`. Что видно на 2026-09-24:

| Где | Наблюдение |
|---|---|
| корень | `graft/` (8,6 МБ, индекс Graft) исключён через `.git/info/exclude`, `graft-lab` — внутри `.git/` (ADR-0026 п. 3). Есть `.obsidian/` (игнорируется) |
| `docs/` | нормативные `00`…`13` с номерами, два файла `10-pack-*` на один номер; `NEXT-SESSION.md` (упраздняется ADR-0032); подкаталоги `adr/`, `archive/`, `integrations/`, `process/` |
| `docs/archive/` | **бинарный `2026-09-22.zip` в git** и файл с пробелом в имени (`SRA-LATTICE-JEV classifier.md`) |
| `docs/integrations/` | нумерованные `00`…`05` рядом с датированным `2026-09-17-sef-platform-design.md` (самый большой файл репозитория — 160 КБ) |
| `docs/process/` | справочники (`graft.md`, `code-search.md`), отчёты (`graft-audit.md`, `graft-report.md`), снимки (`audits/2026-09-24.*`), процедура (`coordinator.md`) — разные виды вперемешку |
| `sra/` | один файл `sra/skills/specification/adversarial-review/SKILL.md` |
| `scripts/` vs `scripts/dev/` | поставляемое (`build`, `golden-*`, `versions-*`) и dev-инструменты (не поставляются — ADR-0026) |
| `.warrant/evidence/test-levels/raw/` | игнорируемый остаток прогона |
| ветки и worktree | 8 локальных и 19 удалённых слитых веток (см. 01) |
| auto-memory | проектная история в личной памяти (ADR-0032 п. 9 — вычистить) |

Мусор копится без владельца: ни одна процедура не отвечает за вопрос «что здесь лишнее».

## Идея

1. **Карта репозитория** — одно место: раздел «Карта каталогов» в `CLAUDE.md` (ADR-0032 п. 7), подробнее —
   `docs/process/structure.md`. Для каждого каталога: назначение, вид содержимого, кто пишет (человек, CLI, генератор,
   OpenSpec), поставляется ли, правило имени.
2. **Правила имён** — коротко, по виду: нормативные документы — `NN-<тема>.md`; ADR — `WARRANT-ADR-NNNN-<slug>.md`;
   датированные (архив, аудиты, черновики, интеграционные черновики) — `YYYY-MM-DD-<тема>`; имена без пробелов,
   латиница, kebab-case; бинарных файлов в `docs/` нет.
3. **Проверка формы** — мета-тест `structure.test.ts`: корень содержит только известные каталоги; имена по правилам;
   нет бинарных файлов в `docs/`; нет пробелов в путях; `docs/drafts/*` — по [../README.md](../README.md).
4. **Навык гигиены** `repo-hygiene` (стандарт ADR-0032 п. 6): периодическая проверка, что лишнее, с удалением после
   подтверждения.

| Проверка навыка | Источник |
|---|---|
| слитые ветки (локальные, origin), worktree слитых веток, worktree без ветки | git (01, G7) |
| файлы передачи потоков, чьи ветки слиты | `docs/handoff/*` |
| папки черновиков, решение по которым уже записано; черновики старше N дней без движения | `docs/drafts/*`, ADR |
| строки `backlog.md` с наступившим триггером («Куда: фаза N» при текущей фазе ≥ N) | реестр долга |
| waivers с `expires_at` ближе 30 дней | `.warrant/waivers/` |
| снимок архитектурного аудита старше последнего тега | `docs/process/audits/` (правило — шаг `/next-session` сейчас) |
| игнорируемые остатки (`.warrant/evidence/**/raw/`, `dist/` в worktree слитых веток) | `git status --ignored` |
| индекс auto-memory длиннее 10 строк, записи `type: project` | ADR-0032 п. 9 (то же предупреждает `brief.js`) |
| битые относительные ссылки в `docs/**/*.md` | линк-чекер |

## Вопросы для grilling

❓ **S1 — Где карта.** Варианты:
- (a) только `CLAUDE.md`;
- (b) `CLAUDE.md` (коротко) + `docs/process/structure.md` (полно);
- (c) `README.md` корня.

➡️ (b): `CLAUDE.md` ограничен 100 строками.

❓ **S2 — Правила имён и что делать с нарушениями.** Принять правила из п. 2 и за один PR привести существующее к ним:
- zip убрать из git (содержимое уже лежит рядом или в истории);
- переименовать файл с пробелом;
- вынести датированный SEF-черновик в `docs/integrations/drafts/` или `docs/archive/`.

➡️ Принять правила, привести одним `docs/`-PR. Для SEF-черновика — отдельный вопрос (память: сверять решения
WARRANT с ним, не терять).

❓ **S3 — Разбор `docs/process/`.** Виды вперемешку. Варианты:
- (a) подкаталоги по виду: `process/reports/`, `process/audits/`; процедуры — в навыки;
- (b) оставить, описать в карте.

➡️ (b) сейчас, (a) — когда файлов станет больше 10. `coordinator.md` проверить: процедура ли он — тогда в навык
`coordinator` по стандарту ADR-0032.

❓ **S4 — `structure.test.ts`: строгость корня.** Белый список каталогов корня (новый каталог — правка теста, то есть
осознанное решение) или только запреты (пробелы, бинарники)?

➡️ Белый список: корень меняется редко, новый каталог верхнего уровня — архитектурное решение.

❓ **S5 — Гигиена: навык, скрипт или оба.** Проверки детерминированы, а скрипт `scripts/dev/hygiene.js` (с unit-тестами)
даёт отчёт. Навык ведёт разбор: что удалить, что оставить, с подтверждением.

➡️ Оба: скрипт находит, навык решает с человеком. `brief.js` показывает только счётчик «гигиена: N пунктов».

❓ **S6 — Когда запускать.** Варианты:
- (a) шаг навыка передачи в конце потока;
- (b) перед spec-PR каждой фазы (вместе с архитектурным аудитом);
- (c) по счётчику `brief.js`.

➡️ (b) + (c). В конце потока — только процедура «после merge» из 01.

❓ **S7 — Удаление: автоматически или с подтверждением.** Удаление ветки на origin, worktree, файла из `docs/` необратимо
для других сессий.

➡️ Всегда список и подтверждение одним ответом на весь список. Исключение — локальные слитые ветки без worktree
(восстанавливаются с origin или через reflog).

## Вне объёма

- Структура `packages/cli/src` — ADR-0030 и `architecture.json`.
- Состав поставляемого пакета — `package-contents.test.ts` (R-15).
