## Context

Сторонний проект `oinsio/clear-progress` держит 23 правила в `.claude/rules/*.md`; часть из них с frontmatter `paths:`
и загружается Claude Code, только когда агент трогает подходящие файлы. Это механизм Claude Code. В MVP код пишет
Codex ([ADR-0018](WARRANT-ADR-0018-frontend-adapters.md), [ADR-0020](WARRANT-ADR-0020-warrant-sef-boundary.md)).

Факты (документация Codex, 2026-09-22):

- Codex собирает цепочку `AGENTS.md` **один раз при старте сессии**: `~/.codex` → корень git → промежуточные каталоги →
  cwd; по одному файлу на каталог (`AGENTS.override.md` сильнее `AGENTS.md`); бюджет — `project_doc_max_bytes`,
  по умолчанию 32 KiB. Вложенный `src/AGENTS.md` читается, только если cwd внутри `src/`. У WARRANT и SEF cwd —
  корень worktree, поэтому загрузки по пути у Codex нет.
- Правила для артефактов OpenSpec уже доставляются адресно: `warrant sync` → `config.yaml` `rules.<artifact>` →
  `openspec instructions` ([ADR-0015](WARRANT-ADR-0015-openspec-sync-contract.md)).
- `warrant guard` в фазе `post` знает путь изменённого файла ([ADR-0019](WARRANT-ADR-0019-post-edit-hints.md)).
- В SEF `AGENTS.md` входит в `protected[]` и сверяется с эталоном пакета (§7.3 черновика SEF).

## Decision

1. **Правило — JSON-объект**, один файл на правило: `rules/` pack или `.warrant/local/rules/`; схема
   `warrant://rule/1`: `{ "id", "paths": [globs], "text", "enforced_by?": "<check-id>" }`. Текст — на английском
   (читает машина). `enforced_by` показывает, какое правило проверяется механизмом (INV-04). Правила для
   артефактов OpenSpec сюда не входят — их канал `openspec-rules`.
2. **Три канала доставки:**
   - **`AGENTS.md`** в корне, целиком генерируется `warrant sync`: только правила с `paths: ["**"]`;
   - **подсказка при правке:** `guard` в фазе `post` добавляет текст правила в `hints[]`, когда агент правит
     файл, подходящий под `paths`;
   - **Context Pack задачи:** правила, чьи `paths` пересекаются с `write_scope` Run (в SEF — с `impact.write`).
   Вложенные `AGENTS.md` не используются.
3. **Повтор.** Текст правила показывается в подсказке один раз за Run на правило; что уже показано, берётся из
   `guard_events[]`. Это исключение из ADR-0019 п. 10 только для текста правил; находки проверок приходят всегда.
4. **Без дублей.** `warrant validate` отклоняет правило, чьи `paths` целиком лежат в `openspec/changes/**`.
   `warrant status` показывает долю правил без `enforced_by` — меру того, что держится только на prompt.
5. **`AGENTS.md`**: первая строка `<!-- generated by warrant — do not edit -->`; побайтная сверка в `validate`,
   как для `config.yaml`; не больше 16 KiB (половина бюджета Codex — место для `~/.codex/AGENTS.md`), превышение —
   ошибка `validate`. Собственные общие правила проекта — local-правила с `paths: ["**"]`, не ручные правки файла.
6. **Context Pack в MVP.** `warrant run start <change> --task <TASK>` кладёт в Context Pack и в JSON-вывод `rules[]`
   (правила, пересекающие `write_scope`). SEF при подготовке попытки вызывает то же самое.
7. **Нет активного Run → `deny`.** `guard` в фазе `pre` отклоняет любую правку без активного Run с подсказкой
   `warrant run start <change> --task …` (INV-10 явно). Люди не затронуты: guard — только в hooks агента.

## Consequences

- Правило «начни с `run start`» — механизм, а не текст `AGENTS.md`.
- `warrant sync` генерирует новый файл вне `openspec/` (`AGENTS.md`); в SEF он — часть эталона
  `.sef/engines/<profile>/` рядом с `.codex/hooks.json` (ADR-0020 п. 14).
- Новая схема `rule/1`, `provides.rules` в pack, `rules[]` в `run start`, проверки `validate` — долг фаз 3–4,
  как у ADR-0016…0021.
- core-sdd правил пока не поставляет: кандидат «не править stable ID» уже в `openspec-rules` и проверяется
  `validate --files`.

## Alternatives

- **Markdown с frontmatter, как `.claude/rules`** — отвергнуто: конвенция WARRANT — JSON с `$schema`.
- **Всё руками в `AGENTS.md`** — отвергнуто: нет адресности, нет `enforced_by`, drift не виден.
- **Вложенные `AGENTS.md`** — отвергнуто: Codex не читает их при cwd = корень.
- **Секция между маркерами в ручном `AGENTS.md`** — отвергнуто: два писателя одного файла.
- **Текст правила при каждой правке** — отвергнуто: шум. **Не показывать, если правило уже в Context Pack** —
  отвергнуто: WARRANT не знает, что агент прочитал.
- **Без активного Run — пропустить правку с finding** — отвергнуто: агент обходит `write_scope` и правила.
