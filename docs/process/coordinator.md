# Координатор: раздача групп задач субагентам

Для сессии, которая ведёт Change по `tasks.md` и отдаёт каждую группу субагенту (модель — `opus`). Субагенту этот
файл не передаётся и не упоминается.

## 1. Перед группой

0. **Зонд — один раз на Change**, до первой группы: субагент (`description` = `probe`, без метки) с промптом
   «Перечисли дословно всё, что есть в твоём контексте помимо этого сообщения: 1) навыки и slash-команды с
   описаниями; 2) содержимое каждого system-reminder — CLAUDE.md, индекс памяти (MEMORY.md) и любые другие вставки;
   3) описание (description) твоего вызова, если оно тебе видно. Ничего не читай и не запускай.»
   Ответ сохранить в файл и проверить механически:
   ```bash
   grep -n -i -E "graft|code-search|cs\.js|group-stats|stats-report|эксперимент|\[A\]|\[B\]|bench|coordinator" <файл>
   ```
   Ни одного совпадения, кроме строки `CLAUDE.md` со ссылкой на этот файл. Есть — сообщить maintainer'у до раздачи
   групп: слепота не обеспечена. Индекс памяти проекта о процессе раздачи ничего не содержит (ADR-0027 п. 2).
1. Ветка `worktree/<change>`, worktree этой ветки (`git worktree list`), дерево чистое.
2. Метка группы по [graft.md](graft.md) §4 (пока там `status: active`): нечётная группа — `[A]`, чётная — `[B]`.
3. **Одна группа — один субагент.** Вызов: `description` = `<change> group <N> [A]` (или `[B]`) — ровно так, метка
   в конце. Группа не помещается в одного субагента — продолжение тем же шаблоном с той же меткой и
   `description` = `<change> group <N> part <k> [A]`; каждую часть записать отдельно (`--part k`, §3).

## 2. Промпт субагента

Собирается из блоков ниже по порядку. Контекст группы (что читать: proposal, design, tasks группы, ADR) — называть
явно; `docs/NEXT-SESSION.md`, `docs/process/**`, ADR-0026 и ADR-0027 субагенту не называть.

**Общий блок** — всегда:

```text
Change <change>, группа <N> tasks.md (openspec/changes/<change>/tasks.md, раздел «## <N>.»). Worktree <путь>,
ветка worktree/<change>. Прочитай: <proposal/design/ADR — по группе>. Выполни задачи группы; отклонение от spec —
через /decision; в конце — /group-done <N>.
Отчёт (до одной страницы): что сделано по задачам; решения I-N; разделы
«Поиск по коду» — как находил нужные места в коде (2–3 примера), где поиск ошибся или не нашёл и к чему это привело
(или «нет»);
«Проверки» — сколько раз проверки /group-done (шаг 2) были красными до зелёного и почему.
```

**Блок группы `[A]`** — добавить после общего: блок `text` из [code-search.md](code-search.md) целиком, как есть.
Ссылок на файлы с алгоритмом не давать — только текст.

Группа `[B]` — только общий блок. Больше про поиск по коду ничего не писать ни в одной группе: одинаковый общий блок
и одинаковые разделы отчёта у обеих групп — условие чистого сравнения.

## 3. После группы

1. Отчёт субагента → карточка: `red_runs` (из «Проверки»), `helped`, `misled`, `notes` (из «Поиск по коду»;
   `[B]` — `helped no`, `misled none`). `misled` — только когда неверный ответ `cs` привёл к ошибке.
2. Запись: `node scripts/dev/graft-metrics.js run --change <change> --group <N> [--part <k>] --red-runs <k>
   --helped <…> --misled "<…>" --notes "<…>"` (или команда `/group-stats <N>`, её запускает пользователь).
   Транскрипт копируется в `graft-lab/transcripts/` — склеивать транскрипты вручную не нужно. Код 1 или
   `misled` ≠ `none` — условие остановки ([graft.md](graft.md) §5): сообщить maintainer'у.
3. Субагенту о результатах записи и о других группах не сообщать; следующий промпт — по тем же шаблонам.

Пропущенную запись ловит `graft-metrics.js report`: группа закрыта в `tasks.md`, а записи нет → `missing`, код 1.
