> Уточнено [ADR-0033](WARRANT-ADR-0033-git-process.md) п. 9: `deny` и у основной сессии — узкий список команд git и `openspec archive`; решения этого ADR о `Read` / `Grep` субагентов не меняются.

## Context

[ADR-0029](WARRANT-ADR-0029-graft-audit-dev-hooks.md) п. 6 поставил хук `PostToolUse`, который после вызова субагента подсказывает, как было бы по навыку `code-search`, и отложил запрет (`PreToolUse deny`) до 2–3 групп без ложных срабатываний. Замер — группы 1–3 impl-PR `arch-boundaries` против базы `test-levels` `[A]` (п. 8), затем разбор транскриптов g1–g5 и grilling 2026-09-24 (решения H-1…H-9, приняты maintainer'ом; [NEXT-SESSION](../archive/2026-09-24-next-session.md), раздел «`PreToolUse deny` — решения grilling»). Факты:

- **Предупреждения поведение не меняли:** после первой подсказки хука — ещё 9 отступлений в g4 и 8 в g5 (обе `compliant: false`: чтения целиком, shell-поиск, `cs` через `head`/`tail`). Ошибок это не дало, но каждое такое чтение — байты в контексте, ради экономии которых навык принят ([ADR-0028](WARRANT-ADR-0028-graft-adoption.md)).
- **Детектор без результата вызова** (режим `PreToolUse`) совпал с режимом `PostToolUse` на 20 из 21 помеченных вызовов. Промах — `python - <<EOF`, читающий файлы изнутри: это видно только по выводу.
- **Одно ложное срабатывание** — g3, `grep` по `edits2.js` в scratchpad координатора: `isCodeFile` считал кодом любой `.ts`/`.js`, а навык — только `packages/**`, `scripts/**` репозитория. Пограничные — `grep -c` по только что записанному файлу кода (g2, g5): формально поиск по коду.
- **Пробелы `cs`:** `impact` для констант и типов неполон — grep-часть искала только вызовы и импорт, использования как значения пропускала (`RISK_LEVELS`: `waive.ts:109–110`; `FALLBACK_ROLE`: `classify.ts:108`, `roles.ts:44`); `cs deps --level 2` считает файлы `core/*.ts` частью модуля `core`, а [ADR-0030](WARRANT-ADR-0030-module-boundaries.md) — отдельными модулями (ложный цикл `core ↔ core/resolve`, I-146).

Условие ADR-0029 п. 6 «без ложных срабатываний» выполняется после сужения области кода (п. 1): единственное ложное срабатывание уходит, настоящие — остаются (п. 6, пересчёт).

## Decision

1. **Код — область навыка, не расширение (H-1).** Код для детектора — файл `.ts`/`.js` под `packages/` или `scripts/` **рабочего дерева WARRANT** (кроме `node_modules`, `dist`, схем, fixtures, golden — как прежде). Корень дерева хук ищет на диске: ближайший `.git` выше пути, в котором есть `scripts/dev/cs.js` (поэтому соседний worktree репозитория — тоже код, другой репозиторий — нет). В пересчёте записей по транскрипту — каталог `SRA` / `SRA-*` на пути. Файлы в scratchpad, temp и других репозиториях, файлы корня дерева вне `packages/`, `scripts/` — не код. Поиск по корню дерева или его предку — по коду, как прежде. Логика — `graft-metrics-lib.js` (`locate`, `isCodeFile`, `coversCode`), unit-тесты.
2. **Что запрещается (H-2)** — всё, что детектор `deviationsOf` находит по входу вызова (без результата — то же, что с результатом): Grep и shell-поиск (`grep`/`rg`/`git grep`/`Select-String`) по коду; Read кода без диапазона или диапазоном на весь файл; `cat`/`sed`/`head`/`Get-Content`/`git show` кода целиком; `head`/`tail` на выводе `cs`; `graft` напрямую (правило 1). Длину файла хук берёт с диска. Файлы до 40 строк — исключение, как в правиле 2. Видимое только по выводу (скрипт, читающий файлы изнутри; чтение, упёршееся в конец файла раньше диапазона) — предупреждение `PostToolUse`, как в ADR-0029.
3. **Только субагенты (H-3):** проверяется вызов, во входе хука которого есть `agent_id`. Основная сессия (координатор) не блокируется: её вызовы выходят из хука до загрузки детектора.
4. **Ответ хука (H-4):** `hookSpecificOutput: { hookEventName: "PreToolUse", permissionDecision: "deny", permissionDecisionReason }`, причина — строка `adviceFor` (правило, что сделано, что сделать вместо), не длиннее 600 символов. `ask` не подходит: фоновому субагенту некого спросить. Сбой или таймаут хука — вызов разрешается (хук не ломает сессию, как в ADR-0029).
5. **Исключений сверх «до 40 строк» нет (H-5)**, в том числе «файл переносится целиком»: перенос — `git mv`, чтение — `cs skeleton` и диапазоны. Выключить локально — `"disableAllHooks": true` в `.claude/settings.local.json`. Запрет мешает законной работе — строка в `notes` карточки группы и повод пересмотреть этот ADR.
6. **Метрики (H-6):** запрещённый вызов не выполнялся. В транскрипте это `tool_result` с `is_error: true`, текст которого — ровно причина хука (`code-search: …`); `graft-metrics` считает его в `tool_calls.blocked`, не в `deviations` и не в байтах (`isBlockedResult`), поэтому замер после запрета сравним с базой. Пересчёт (`rescore`) записей после п. 1: `arch-boundaries` g3 — отступлений 2 → 1 (ушёл `grep` по scratchpad), остальные 16 записей (`test-levels`, `phase-3b`, `arch-boundaries`) не изменились.
7. **`cs impact` для не-функций (H-7).** Если символ не функция и не метод в графе (константа модуля, тип, метод интерфейса, имя вне графа), grep-часть ищет каждое вхождение `\bNAME\b` (`Type.name` — `\.name\b`), а не только вызовы и импорт; объявление `const NAME` уровня модуля — определение, остальные строки — места. Вывод говорит `match: word`; JSON `cs-impact/1` получает поле `match` (`calls` | `word`). Unit-тесты `cs-lib`; вопрос **q18** бенчмарка («какие функции используют `RISK_LEVELS`»).
8. **`cs deps --level` против модулей-файлов ADR-0030 — долг (H-8).** В навыке — строка: модули-файлы `core/*.ts` в `cs deps --level` входят в `core`; границы модулей — `architecture.json`.
9. **Форма (H-9):** `.claude/settings.json` получает событие `PreToolUse` с matcher `Read|Grep|Bash|PowerShell` (Glob детектор не помечает никогда) и командой `node "${CLAUDE_PROJECT_DIR}/scripts/dev/cs-hook.js" pre-tool`; форму держит `test/unit/meta/dev-hooks.test.ts`, решение — `cs-hook-lib.js` (`hookResponse`, unit-тесты). Проверено живым зондом `claude -p` (Claude Code 2.1.263) с субагентом `general-purpose` в worktree: у субагента Grep и `grep -rn` по `packages/cli/src` и Read `core/errors.ts` (99 строк) целиком — отказ, причина дошла до модели текстом ошибки инструмента; Read `core/ctx.ts` (22 строки) целиком — выполнен; тот же Grep в основной сессии — выполнен.

## Consequences

- ADR-0029 п. 6 уточнён: `PostToolUse` остаётся для видимого только по выводу; всё видимое по входу — запрет. Навык `code-search`, [coordinator.md](../../.claude/skills/change-coordinate/SKILL.md) (отказы хука в отчёте, `blocked` в карточке), [graft.md](../process/graft.md) §3–§5 — по этому ADR.
- Субагент, получивший отказ, делает то, что написано в причине, — в зонде он так и сделал; обойти можно скриптом, читающим файлы изнутри (п. 2), — это видно предупреждением и в `deviations`.
- Каждый Read/Grep/Bash/PowerShell любой сессии запускает node (~150–200 мс) ещё раз — до вызова; вызовы основной сессии выходят сразу после разбора входа.
- Число `blocked` в записи группы — новый сигнал наблюдения (ADR-0028 п. 5): много отказов при `compliant` — навык неудобен для задачи, повод разобрать `notes`.

## Alternatives

- **Оставить предупреждения** — отвергнуто: не меняли поведения (9 и 8 отступлений после подсказки в g4 и g5).
- **`permissionDecision: "ask"`** — отвергнуто: фоновый субагент не может спросить человека (H-4).
- **Запрет и для основной сессии** — отвергнуто: координатор читает код редко и по делу (сверка отчёта, ручная проверка); блокировать его — тормозить процедуру без выигрыша в байтах субагентов (H-3).
- **Исключение «файл переносится целиком»** — отвергнуто: `git mv` и диапазоны покрывают перенос; исключение по намерению не проверяемо (H-5).
- **Область кода по расширению, без дерева** — отвергнуто: ложное срабатывание g3 (H-1).
- **Считать отказ отступлением** — отвергнуто: вызов не выполнялся, байтов нет; замер стал бы несравним с базой (H-6).
