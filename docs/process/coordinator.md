# Координатор: раздача групп задач субагентам

Для сессии, которая ведёт Change по `tasks.md` и отдаёт каждую группу субагенту (модель — `opus`).

## 1. Перед группой

1. Ветка `worktree/<change>`, worktree этой ветки (`git worktree list`), дерево чистое, в worktree выполнен `npm ci`
   (для тестов; `scripts/dev/cs.js` зависит только от node).
2. **Одна группа — один субагент.** Вызов: `description` = `<change> group <N>`. Группа не помещается в одного
   субагента — продолжение тем же шаблоном, `description` = `<change> group <N> part <k>`; каждую часть записать
   отдельно (`--part k`, §3). Следующей части — в промпт сводку предыдущей: что сделано, какие файлы и символы
   уже разобраны (`file:line`), чтобы она не перечитывала их.

## 2. Промпт субагента

Контекст группы (что читать: proposal, design, tasks группы, ADR) — называть явно.

```text
Change <change>, группа <N> tasks.md (openspec/changes/<change>/tasks.md, раздел «## <N>.»). Worktree <путь>,
ветка worktree/<change>. Прочитай: <proposal/design/ADR — по группе>. Выполни задачи группы; отклонение от spec —
через /decision; в конце — /group-done <N>.
Отчёт (до одной страницы): что сделано по задачам; решения I-N; разделы
«Поиск по коду» — как находил нужные места в коде (2–3 примера), где поиск ошибся или не нашёл и к чему это привело
(или «нет»); ответы `cs`, которые были пустыми или неполными, — что сделал вместо них; отказы хука, мешавшие законной
работе, — какой вызов и что сделал вместо (или «нет»);
«Проверки» — сколько раз проверки /group-done (шаг 2) были красными до зелёного и почему.
```

Строки про навык `code-search` в промпте нет: указатель на навык, `cs impact` и карту репозитория субагент получает
хуком `SubagentStart` ([ADR-0029](../adr/WARRANT-ADR-0029-graft-audit-dev-hooks.md) п. 6); вызов, нарушающий навык по
своему входу, хук `PreToolUse` отклоняет до выполнения с причиной «что сделать вместо»
([ADR-0031](../adr/WARRANT-ADR-0031-pretooluse-deny.md)), нарушение, видимое только по выводу, — подсказка `PostToolUse`
в том же ходе. Координатора (основную сессию) хуки не ограничивают. Хуки не сработали (нет `.claude/settings.json` в worktree, `disableAllHooks`) —
добавить в промпт: «Поиск по коду — строго по навыку code-search: прочитай его до первого обращения к коду».

## 3. После группы — наблюдение (ADR-0028 п. 5, ADR-0029 п. 8, ADR-0031)

1. Отчёт субагента → карточка: `red_runs` (из «Проверки»), `helped`, `misled`, `notes` (из «Поиск по коду»).
   `misled` — только когда неверный ответ `cs` привёл к ошибке (красный прогон, неверная правка).
2. Запись: `node scripts/dev/graft-metrics.js run --change <change> --group <N> [--part <k>] --mode on
   --red-runs <k> --helped <…> --misled "<…>" --notes "<…>"` (или `/group-stats <N>`). Транскрипт копируется в
   `graft-lab/transcripts/`. `misled` ≠ `none` или `compliant: false` — сообщить maintainer'у: `misled` — условие
   пересмотра ADR-0028 и повод добавить вопрос в бенчмарк ([graft.md](graft.md) §5). Отказы хука — `tool_calls.blocked`
   записи (не отступления, байтов нет). Первые 2–3 группы после ADR-0031 сравнить с `arch-boundaries` g1–g3 и базой
   `test-levels` `[A]` ([graft.md](graft.md) §5); отказ, мешавший законной работе, — в `notes` и maintainer'у (повод
   пересмотра ADR-0031 п. 5).
