## Сквозные вопросы — задать первыми

❓ **X1 — Место черновиков.** В таблице ADR-0032 п. 1 нет строки «черновики / идеи до решения». Варианты:
- (a) поправка к ADR-0032 — строка `docs/drafts/` и правило из [../README.md](../README.md);
- (b) считать черновик частью передачи потока.

Сейчас `docs/drafts/` нет ни в таблице ADR-0032, ни в «Карте» `CLAUDE.md`, а `dev-context.test.ts` его не проверяет.

➡️ (a): у черновика свой жизненный цикл (удаляется PR решения), и он больше 60 строк передачи. Строка в «Карте»
`CLAUDE.md` и проверка формы — тем же PR.

❓ **X2 — Имена навыков.** Сейчас имена разного вида: `decision`, `group-done`, `handoff`, `code-search`,
`architecture-audit`. Вариант — префикс области: `git-*`, `change-*`, `review-*`, `repo-*`. Так список навыков в
каждой сессии группируется сам.

➡️ Префикс области для новых навыков, существующие не переименовывать: навыки процедур уже вошли в привычку.

❓ **X3 — Хуки для основной сессии.** ADR-0031 запрещает только субагентам (`agent_id`). Правила git (01, G3, G6), гигиены (03)
и запрет `openspec archive` (02, A7) нарушает как раз основная сессия. Расширять ли `PreToolUse deny` на основную сессию для узкого списка
команд git и `gh`?

➡️ Да, отдельным пунктом нового ADR. Белый список команд, по которым решает хук, — в `dev-hooks.test.ts`.

❓ **X4 — Порядок потоков.** Одного места, где виден порядок потоков, нет. `brief.js` перечисляет файлы передачи, но не
показывает, что `phase-4` ждёт `skills-git-hygiene`: зависимость записана только прозой в разделе «Цель» `phase-4.md`.
Когда потоков станет три и больше, порядок будет виден, только если прочитать все файлы. Варианты:
- (a) строка `После: <поток>[, <поток>]` сразу под заголовком файла передачи. `brief.js` печатает потоки в порядке
  зависимостей и помечает ждущие («ждёт skills-git-hygiene»), `dev-context.test.ts` проверяет, что поток из «После»
  существует (файл передачи в `main` или в worktree) и циклов нет;
- (b) отдельный файл `docs/handoff/README.md` с порядком — второе место того же знания (ADR-0032 п. 1);
- (c) приоритет числом (`Приоритет: 1`) — сравнивать числа из разных файлов, написанных разными сессиями, хрупко;
- (d) оставить прозой в «Цели».

➡️ (a): зависимость живёт в файле того потока, которого она касается, а порядок вычисляется (ADR-0032 п. 1, 4).
Поправка к ADR-0032 п. 3 (форма файла передачи) и п. 4 (вывод `brief.js`). Поток, у которого зависимость ещё не
закрыта, остаётся в выводе с пометкой. Закрытая зависимость — строку «После» удаляет последний PR потока-предшественника
(вместе со своим файлом передачи, 02, A6).
