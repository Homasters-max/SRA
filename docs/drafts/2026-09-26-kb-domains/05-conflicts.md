# Противоречия, найденные нарезкой доменов

## Проблема

Нарезка сверяла документы между собой и с кодом (через `cs`). Найдено 37: `lifecycle` — 27, `kernel` — 10. Полные списки — `.kb-search/domains/CONFLICTS-lifecycle.md`, `CONFLICTS-kernel.md` (unit, вид, что расходится, источник). Виды:
- **документ ↔ документ / код** — ошибка или отставание документа, либо код без нормы. Примеры: 06a §3 требует review HIGH-риска в CI, ADR-0034 п. 10 и код принимают локальный (`verdict.ts#attestationAccepted`); 05 §7 обещает `EXPIRED` у waiver, код его не пишет; REQ-KRN-012 без `spec_tree` (ADR-0036 п. 3 и схема — с ним); 06 §3 — waiver спасает только FAIL, REQ-VER-003 и код — ещё BLOCKED; ADR-0021 разрешает factory-change трогать архив, REQ-VER-004 и `scopeViolations` — нет; `renumber` переписывает record в обход CLI (REQ-KRN-024, ADR-0012 п. 1); ADR-0006 «сортировка ключей» против порядка по схеме (REQ-KRN-022).
- **4c** — принятый ADR-0037 меняет норму, код фазы 4c ещё не написан (`--ref` у MERGED — URL impl-PR, REF_MISMATCH — «два run», human-approval по слитому PR …): долг реализации, не ошибка документа. Автоматическая разметка вида в `CONFLICTS-*.md` нашла 8 таких, нарезка ADR-0037 — 13: перепроверить.

## Идея

Каждое противоречие — одно из: поправить документ (обычным путём: ADR / Change / archive-PR для main specs), поправить код (Change или `fix/`), принять расхождение (I-N или ADR), закрыть как «4c» (снимется impl-PR phase-4c).

## Вопросы для grilling

1. Разбирать все 37 или только «документ ↔ код»? Рекомендация: «4c» — отдать в impl-PR phase-4c списком; остальные (~24) — grilling по одному, начиная с тех, что держат безопасность (06a §3 review HIGH, renumber в обход CLI).
2. Куда записывать: backlog (одна строка на противоречие) или один Change «doc-drift»? Рекомендация: backlog, группы по документу; исправления документов без изменения поведения — одним docs-PR.
3. Сделать поиск противоречий регулярным (нарезка — часть аудита перед spec-PR фазы)? Рекомендация: да, после 01-storage.
