Обновить файл передачи контекста `docs/NEXT-SESSION.md` по фактам сессии.

Вход: `$ARGUMENTS` — необязательная сводка сессии от пользователя. Источник фактов — репозиторий и сессия, не догадки.

**Шаги**

1. **Собрать факты.**
   ```bash
   git branch --show-current
   git log --oneline -20
   git worktree list
   git tag --list 'v*' --sort=-v:refname
   node packages/cli/dist/bin/warrant.js --version
   node packages/cli/dist/bin/warrant.js status
   ```
   Плюс: `openspec/changes/*/tasks.md` активных Changes (открытые `- [ ]`), новые строки `I-N` в их design.md, новые ADR
   в `docs/adr/`, результаты проверок, если они запускались в сессии. Ветка/worktree сессии — из вывода, не из памяти.

2. **Прочитать `docs/NEXT-SESSION.md` целиком** и найти разделы: «Состояние на <дата>», таблицы долга («Долг после
   фазы …», «Не исправлено …», «Долг схем и CLI …»), блок «Продолжение — готовый запрос», таблицу «Процессные правила →
   чем держатся».

3. **«Состояние».** Дату заголовка — на сегодня; дописать/заменить пункты: что закрыто (PR, commit, tag), версии CLI и
   packs, результаты прогонов. Устаревшие пункты сократить до одной строки со ссылкой, не удалять факты о релизах.

4. **Долг.** Строки, закрытые в сессии, — зачеркнуть `~~…~~` с пометкой «закрыт <чем>»; новые долги — строками с
   направлением «Куда». Решение по строке, которого нет в сессии или в документах, не придумывать — оставить строку как
   есть или записать вопрос к maintainer'у.

5. **Готовый запрос.** Переписать блок ```` ```text ```` под следующий шаг: что прочитать, какая ветка/worktree, какая
   группа/фаза, что спросить у maintainer'а.

6. **«Процессные правила → чем держатся».** Для правила, у которого в сессии появилась проверка (тест, `validate`, шаг CI,
   процедура `.claude/commands/`), обновить колонку «Чем держится»; новые правила — только если они приняты в сессии.

7. **Frontmatter**: `title` — следующий шаг. Затем
   ```bash
   node packages/cli/dist/bin/warrant.js validate
   git diff --stat docs/NEXT-SESSION.md
   ```
   Показать пользователю diff разделов. Не коммитить без его подтверждения (или в рамках `/group-done`).
